## 맥락

새벽 세션이 `connect_readonly` 가 실은 전 모터에 `0xFC` 를 보낸다는 것을 실기에서
찾아냈다. 기록은 워크로그와 기억에 남겼는데 **코드는 아직 반대로 말하고 있었다.**

그리고 사용자가 릴레이·컨택터를 달 계획이 아예 없음을 확정했다. NORM-007 판정이
2026-07-16 에 이미 같은 결론을 냈으나 GUI 는 반대로 구현돼 있었고, 그 판정을 집행할
검사(`enforcement.status: planned`)는 쓰인 적이 없다.

## 결과 ① — 거짓 주장이 검사 안까지 들어가 있었다

`tests/wp102/conftest.py` 의 `FakeDamiaoBus.connect()` 가 `handshake` 인자를 실제
시그니처 그대로 받아놓고 **버렸다**. 클래스 독스트링은 *"It opens no socket and enables
no torque"*. 그 위에서 테스트가 단언했다:

```python
# The bring-up sent no torque-enable command of any kind.
assert not any("enable" in command for command in bus.commands)
```

가짜가 벤더 동작이 아니라 **독스트링의 믿음**대로 쓰였고, 검사는 그 믿음을 자기 자신에게
되물었다. 실기가 어떻든 빨간불이 될 수 없는 구조다.

수리: 가짜가 핸드셰이크 인에이블을 `HANDSHAKE_ENABLE` 로 기록한다. 단언을 참인 것으로
바꿨다 — `enable_torque`/`enable_all` 부재 **+ 핸드셰이크 인에이블 존재를 못박음.**

`is_torque_enabled` 는 그대로 두되 무엇인지 적었다: **이 클래스가 명령한 것이지 모터
상태가 아니다.** 이름을 바꾸면 파급이 크고, 이름이 아니라 그것을 증거로 읽는 것이 결함이다.

## 결과 ② — 하드 E-Stop 을 컨트롤에서 뺐다

`13 §2.7` 포트 매니페스트가 이 시스템의 전 네트워크 경계를 전수 열거하는데 릴레이·컨택터·
GPIO·안전 PLC·E-Stop 접점이 **0행**이다. 원장의 표현: *"아무것도 하지 않는 버튼이 아무
버튼도 없는 것보다 나쁘다."*

타입으로 막았다. `HARD_ESTOP: StopKindSpec`(핸들러를 받는 정지) →
`PHYSICAL_ESTOP: PhysicalStopSpec`. **핸들러를 붙일 자리가 타입에 없다.**

CSS 가 조용한 함정이었다. `.oa-stop` 베이스에 `cursor: pointer` 가 있어서, `<div>` 로만
바꾸고 두면 **손가락 커서가 뜨는데 안 눌리는 패널**이 된다 — 원래보다 나쁘다. 꽉 찬 빨강도
테두리뿐인 소프트 스톱 옆에서 더 눌러야 할 것처럼 보인다. 점선 테두리 + 투명 배경 +
`cursor: default` 로 바꿨다.

낙하 경고(`FR-GUI-064`)는 유지한다 — **없애는 것은 버튼이지 위험이 아니다.**

## 팀원 저장소에서 확인한 것 (다시 재지 않아도 되는 값)

`bh_remy_openArm` 은 같은 벤치다 — PCAN-USB Pro FD 한 장치 두 채널, 시리얼이 같은
Arducam B0495 두 대(`202500915_0001`), ZED-M. 원본에서 직접 확인한 것:

- **Arducam 을 설정 없이 열면 `exposure_time_absolute=660` · `gain=1600` 둘 다 최대라
  전 프레임 순백 클리핑**(`decisions.md:918-922`). 살린 값 exposure=60 · gain=200 ·
  WB=4000 K. 우리 저장소에 `exposure`/`CAP_PROP`/`FOURCC`/`white_balance` 가 **0건**이므로
  카메라를 꽂으면 그대로 660/1600 으로 열린다.
- **ZED-M 은 USB 런타임 자동절전에 서스펜드되는 대신 버스에서 떨어진다**
  (`decisions.md:681-694`). 40초에 device 번호 2회 변경 + 1회 소실, 같은 시간 Arducam 은
  불변. `usb_link.probe_usb_link` 가 `2b03:f682` 를 못 찾는 사유가 케이블이 아닐 수 있다.
- **`NEURAL*` 깊이 모드는 TensorRT 없으면 `CORRUPTED SDK INSTALLATION` 으로 죽는다** —
  진단 메시지가 원인을 반대로 가리킨다. 도는 조합은 `DEPTH_MODE.ULTRA`.
- **정지마찰 실측 밴드** DM8009 0.12~1.44 · DM4340 0.14~0.97 N·m(`decisions.md:340-343`).
  우리 `friction.provisional.yaml` 의 `Fo+Fc` 는 J1 1.555 · J2 1.940 · J3 1.170 · J4 1.037 로
  **계통적으로 10~35% 높다** — 우리 합성값이 보수적(과대)이라는 뜻.
