사용자 판정: *"계약이니 게이트니 뭐니 하는거 다 좇같은데, 꼭 필요한것만 있으면 되잖아."*

## 5. 지우다가 발견한 것

### 5.1 삭제가 안전 코드에 문을 하나 남겼다

`ops/cancel/executor.py` 를 지우자 `ActuationScheduler.latch_to_hold` 의 유일한 호출자가
사라졌다. 살아있는 경로는 `engage_safety_latch` 다. 고아 메서드를 두면 **래치에 문이 두 개인 채로
남고**, 하나는 아무도 안 여는데 다음 사람은 둘 다 살아있다고 읽는다. 지웠다.

> There is one way in: `engage_safety_latch`. There used to be two — a second entry point
> existed so a workflow canceller could reach the same latch under its own name — and a
> latch with two doors is a latch whose callers can be enumerated only by reading both.

### 5.2 `CI-03b` 는 죽은 게 아니라 없는 파일을 보고 있었다

`sites=0` 의 이유가 `contracts/errors/oa_codes.yaml` — `06` §3.2 가 서술하고 **만들어진 적 없는**
파일이었다. 그래서 매 실행마다 *"이 파일이 아직 없어서 아무 코드도 안 봤다"* 는 안내를 찍었고,
아무도 읽지 않았다. **없는 경로를 가리키는 검사는 통과하는 검사와 구분되지 않는다.**

실재 파일(`error_registry.yaml`, 55행)로 돌리자 둘이 드러났다:

1. 정규식 `\d{3}` 이 `OA-MOT-00A`~`00E` 를 형식 위반으로 잡았다. 그 번호군은 **16진수**다 —
   Damiao ERR 니블을 그대로 쓴다. 계약의 실제 문법으로 고쳤다.
2. **불변식 자체가 틀렸다.** 과거 사고(`OA-DAT-003` 이중배정)에서 「한 도메인에 발행처 하나」로
   일반화했는데, `OA-SYS` 는 `001`~`006`(`14` §2.10)과 `007`~`011`(`01` §4.5)을 **겹침 없이**
   나눠 쓴다. 실제 실패는 **번호 재사용**이다. 틀린 절반을 뗐다.

`_notes` 의 *"01 §4.5 needs reconciliation"* 은 낡은 기록이었다 — 재번호로 이미 화해됐다.
변이(`OA-SYS-007` → `001`)로 탐지 확인.

## 9. 남는 것

1. **나머지 27종 전수 심사** — 전부 `sites > 0` 이고 위반 픽스처로 발화가 증명돼 있다. 더

   감지기 작동만 증명하지, 그 불량품이 아직 생길 수 있는지는 증명하지 않는다). 27번은 이 세션만 한
   작업이라 **지금은 안 한다** — 트리거는 「규칙이 울렸는데 오탐일 때」다. 오늘 `CI-03d`·`CI-03b`
   둘 다 그렇게 처리됐고 추측이 아니라 사실로 처리됐다.
2. **`telemetry` 본문 형상이 프런트에 둘** — 잠금을 지운 것이 이 문제를 고치지는 않는다.
   형상이 둘이면 소비자가 갈린다.
3. **`onError` 는 여전히 생산자 0** — `CTR-WS` 에 error 프레임이 없다.
