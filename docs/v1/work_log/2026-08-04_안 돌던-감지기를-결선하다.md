# 2026-08-04 — 안 돌던 감지기를 결선하다, 그리고 내가 만든 결함

같은 날 `2026-08-04_거짓-안전-주장-제거와-전원차단-배제.md` 의 후속. 그 세션이 찾아낸
"만들어졌고 테스트도 통과하는데 아무도 안 부르는" 다섯 건 중 둘을 손봤다.

## 맥락

게이트 조사가 두 건을 찾았고 직접 확인했다:

- `CollisionGuard._latched` 는 `guard.py:192` 에서만 True 가 되고, 그 줄은 `_latch()` 안,
  `_latch()` 는 `poll()` 안에서만 불린다. **`guard.poll()` 의 프로덕션 호출자가 0개.**
  그런데 `enforcement.py` 는 `collision_latched=self._guard.is_latched` 를 읽는다 —
  **상수 `False` 를 안전 판정에 넣고 있었다.**
- `CommLossWatchdog(` 의 생성 지점 3개가 전부 테스트. 이 리그의 모터는 RID 9 = 0
  (모터측 워치독 OFF) 이라, 통신 두절 시 브레이크 없는 팔을 잡아줄 것이 이것뿐이다.

## 결과 ① — 충돌 가드가 실제로 폴링된다

폴을 `ActuationGateway.submit` 안, 게인 검증보다 **앞**에 놓았다. 같은 호출에서
`is_latched` 를 읽으므로 다른 곳에서 폴하면 래치가 한 명령 늦는다.

**`guard_sample` 을 기본값 없는 필수 키워드로 만들었다.** 기본값을 주면 "버스를 본 적 없는
호출자"와 "보고 정상이라 확인한 호출자"가 구분되지 않고, 그건 고치려는 결함을 위치만 옮겨
재현하는 것이다. 프로덕션 2곳·테스트 약 30곳을 손으로 채웠다.

### 설계가 틀렸던 지점 하나

계획은 `observation_present = all(motor in states for motor in fitted)` 를 생존 신호로 봤다.
그러나 벤더 `DamiaoMotorsBus.sync_read_all_states`(damiao.py:655-674)는 **응답하지 않은
모터에도 캐시 엔트리를 복사해 돌려준다.** 실기에서 이 식은 상수 True 다.

그래서 두 필드를 갈랐다 — `bus_read_ok` 는 벤더가 남기는 `Packet drop:` 로그
레코드(`DropCounter`)로만 판정하는 진짜 생존 사실, `observation_present` 는 응답 매핑이
장착분을 덮었는지 보는 구조적 사실.

### 첫 틱 영구 래치를 어떻게 피했나

`_fail_closed_cause`(guard.py:180-188)는 blind 조건에서 **디바운스 없이 즉시** 래치한다.
잔차를 못 재는 상태에서 그냥 폴을 꽂으면 팔이 못 쓰게 된다.

`residual_exceeded` 를 이름 있는 상수 `NO_RESIDUAL_DETECTION = False` 로 두고, 탐지가
무장되지 않았음을 세 근거로 확인해 주석에 파일:줄로 남겼다 —
`detection_gate/activation.py:254-262` 가 PG-FRIC-001 비-PASS 에서 DISABLED 를 결의하고,
`threshold/activation.py:76-81` 의 FR-SAF-014 가속도 한계가 stock v2.0 자산에서 REFUSE 이며,
`MomentumObserver(` 는 tests/ 밖 인스턴스가 0개다.

**무장 안 된 탐지기가 "임계 초과를 보고한 적 없다"는 참인 진술이다.** 이걸 blind 로 읽으면
3회째 명령에 래치된다.

내 수리를 검증하려고 변이를 두 번 돌렸는데 둘 다 통과했다. 원인은 워크플로가 그 코드를 바꿔
`str.replace()` 의 대상이 사라진 것 — **변이가 아예 적용되지 않았다.** 출력은 "변이해도
통과한다"와 완전히 같다.

세 번째에 `assert n != t, "MUTATION DID NOT APPLY"` 를 넣고서야 진짜 결과가 나왔다(RED 2건).
**변이 검사는 적용 여부를 단언한 뒤에 돌려야 한다.**
