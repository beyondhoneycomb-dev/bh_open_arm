## 2. 대신 지은 것 — 화면이 부르는 표면

**이게 이 저장소에서 프런트가 백엔드에 닿는 첫 `fetch` 다.** 그전까지 `frontend/src` 전체에
`fetch(` 가 0건이었다.

| | 어디 |
|---|---|
| 스캔 | `GET /api/cameras/devices` → `{devices, slots, unboundPorts}` |
| 지정 | `PUT /api/cameras/slots/{슬롯}` body `{portPath}` |
| 해제 | `DELETE /api/cameras/slots/{슬롯}` |
| 프리뷰 | `GET /api/cameras/devices/{포트}/preview` → JPEG 한 장 |
| 저장 | `~/.config/openarm/camera_binding.json`, 원자적 |

**모든 응답이 전체 스캔이다.** 바뀐 필드만 돌려주지 않는다 — 지정은 카메라를 다른 슬롯에서
빼올 수 있고, 로컬로 상태를 패치하는 패널은 밀려난 슬롯을 여전히 차 있다고 그린다.

### 프리뷰가 스트림이 아니라 스틸인 이유

슬롯의 진짜 스트림은 캡처 런과 실시간 채널의 것이다. 같은 노드에 두 번째 리더를 열면 런이 세고
있는 프레임을 가져가고, **런은 그걸 카메라가 드롭하기 시작한 것과 구분하지 못한다.** 한 장씩
열고 닫으면 캡처에 끼어들 수가 없다. 이미 잡혀 있으면 기다리지 않고 `503` 으로 "캡처가 쥐고
있다"고 답한다 — 런 중에는 그게 맞고 영구적인 답이다.

프리뷰는 슬롯의 선언 포맷을 강제하지 않는다. 그 포맷은 **슬롯의** 것이고, 아직 슬롯이 없는
장치에는 없다. 강제하면 식별이 제일 필요한 카메라가 프리뷰가 안 되는 카메라가 된다.

캐시 버스터(`?t=`)는 장식이 아니다. 없으면 브라우저가 첫 프레임을 영원히 준다 — 카메라가 더는
보지 않는 장면을, 도는 프리뷰처럼.

### 실패하면 픽스처로 안 돌아간다

`useCameraDevices` 는 스캔이 실패하면 목록을 **비운다.** 픽스처 세 줄을 남기면 백엔드가 없는데
그럴듯한 카메라 세 대가 뜨고, 운영자는 없는 카메라에 슬롯을 배정한다. 에러 문구만 남긴다.

`source` prop 을 준 호출자(픽스처·테스트·나중 통합 웨이브)는 자기가 몰고 있는 것이므로 스캔을
안 한다. 안 준 경우만 실기에 붙는다.

## 3. 데드코드 — 지운 게 아니라 소비됐다

어제 "프로덕션 호출자 0"으로 보고했던 것들을 다시 셌다.

| 심볼 | 어제 | 오늘 |
|---|---|---|
| `portpath.node_by_port` | 호출자 0 | `snapshot.grab_jpeg` 가 쓴다 |
| `portpath.discovery_rows` | 호출자 0 | `camera.api.device_rows` 가 쓴다 — 독스트링이 *"the rows the camera screen assigns against"* 라고 적혀 있었다. 죽은 게 아니라 소비자가 안 온 것이었다 |
| `portpath.assert_ports_distinguish` | 내부 2 | 위 둘 + `rig.check_binding` |
| `video_device_nodes`·`query_capture_node` | 외부 0 | `portpath` 내부 헬퍼. 살아 있다 |

**카메라 트리에 호출자 0인 심볼은 이제 없다.** 어제 죽어 보였던 이유는 소비자를 아직 안 지어서다.

### 죽은 심볼을 쫓다 찾은 구멍

`node_by_port` 는 포트를 찾기 전에 `assert_ports_distinguish` 를 먼저 부른다. 내가 어제 지은
`rig.check_binding` 은 `{node.port_path: node}` dict 를 직접 만들면서 **그 검사를 건너뛰었다.**
같은 포트에 노드가 둘이면 dict 가 나중 것을 조용히 남기고, 슬롯은 열거 순서를 가리키게 된다 —
`06` FR-CAM-004 가 거절하는 바로 그것이 포트 경로를 쓰고 있는 꼴이다. `check_binding` 이
이제 먼저 거절한다. `test_camera_api.py` 의 `two_cameras_on_one_port` 가 `409` 를 확인한다.
