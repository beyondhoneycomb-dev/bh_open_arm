그리고 **내가 반복해서 잘못 말하던 것 하나의 정정**이다.

## MJPEG — 커널에 물었다

```
Arducam L /dev/video0   [0] YUYV  YUYV 4:2:2  uncompressed
Arducam R /dev/video4   [0] YUYV  YUYV 4:2:2  uncompressed
ZED-M     /dev/video2   [0] YUYV  YUYV 4:2:2  uncompressed
```

`VIDIOC_ENUM_FMT` 전수. **세 대 다 포맷이 하나뿐이고 MJPEG 은 목록에 없다.** 옆 레포는 Arducam
데이터시트(`Output Format: YUY2`, 단수)로 같은 결론을 적었고 여기서는 ZED 까지 포함해 커널에
직접 물었다.

그리고 MJPG 을 요청하면 **조용히 YUYV 로 협상되고 `frame_ok=True` 가 돌아온다.** FOURCC 를
해상도보다 먼저 박는 규칙과 `pixel_format_finding` 이 존재하는 이유가 이것이다.

따라서 대역폭을 줄이는 지렛대는 압축이 아니라 해상도·fps 뿐이다(현재 3096.6 / 3200 Mbps).

## 🔴 정정 — 전원차단 드릴을 "남은 일"로 계속 읊었다

`WP-5-06/07` 을 통짜 실기·사람 항목으로 목록에 올려왔다. **틀렸다.** 계획서
(`02c` §4.6-4.7)가 드릴마다 실행클래스를 따로 준다:

| 드릴 | 실행클래스 |
|---|---|
| D-E 학습 OOM | **`AI-offline`** — 하드웨어 0, *"로봇에는 영향 없음"* |
| D-B 스레드 사망 · D-D CAN 침입자 · D-F 추론 단절 | **`AI-on-HW`** — 사람 불필요 |
| D-A 백엔드 사망 · D-C bus-off · D-G 전원상실 | `Human-assisted-HW` |

`WP-5-06` 수용게이트 10개도 마찬가지다 — ①③④ 는 **정적 검사**(`READ_POSITIONS` 가 `CONNECT`
앞 · 사람 확인 전 자동이동 경로 0 · `q_des=0` 경로 0), ②⑥ 은 **결함주입**, ⑦⑧⑨ 는 캘리브 파일
내용. 실제 통전이 필요한 것은 ⑤(저 kp 홀드 3초, 진동/발산 없음) 하나다.

그리고 물리 쪽은 **옆 레포가 이미 답했다** — `bh_remy_openArm/docs/decisions.md:174-186` **D10**:

> **E-stop — 하드웨어 존재, 소프트웨어는 측정만.** 버스 전원을 SW·IO 와 독립적으로 끊는
> **하드웨어 E-stop 이 이미 물리적으로 존재한다(사용자 확인)** … 하드웨어로 이미 충족.
> **뒤집히는 조건: 없음.**

우리 `NORM-007`(*"하드 E-Stop = 전원라인 물리 버튼(사람 손)뿐"*)과 모순 없이 맞물린다. 우리
저장소에 없는 것은 **SW 제어 전원차단 경계**이지 물리 E-Stop 이 아니다.

**남은 일 목록을 쓸 때 WP 를 통짜로 읽지 말 것.** 실행클래스는 WP 가 아니라 그 안의 단계·드릴에
붙는다.

## 🔴 그런데 `WP-5-06` 은 소유 경로가 없다

`registry/traceability.yaml` 의 `WP-5-06` 레코드는 `owns: []` 이고 두 phase(`SHAPE-HG` ×2,
`Human-assisted-HW` / `Human-judgment`)도 각각 `owns: []` 다.

즉 **그 이름으로 코드를 착지시킬 자리가 계획서에 없다.** 11단계 `RecoveryState` 상태머신
(`POWER_RESTORED → … → READ_POSITIONS → ZERO_INTEGRITY → HUMAN_POSE_CONFIRM → … → CONNECT → …`)은
전수 검색 0건으로 아직 없는데, 새 파일을 어느 트리에도 넣을 수 없다 — CI-02b 가 소유 글로브
없는 파일을 거부한다.

`backend/crash_recovery/` 는 이름이 비슷하지만 **`WP-3C-07`(데이터셋 크래시 복구 — parquet 푸터·
비디오 세그먼트)**이고 팔 전원상실과 무관하다.

**사용자 결정 필요**: 이 상태머신의 코드 집을 어디로 할 것인가(기존 WP 확장 vs 새 소유 경로 선언).

## 🔴 `uv sync` 가 pyzed 를 지운다

`oa-camcap` 을 콘솔 스크립트로 등록하고 `uv sync --extra dev --extra robot` 를 돌렸더니
**`pyzed` 와 `cython` 이 제거됐다.** 락파일에 없는 패키지를 uv 가 쳐낸다 — pyzed 는 벤더 휠을
손으로 넣은 것이라 락에 들어갈 수 없다.

복구 2단계(sudo 불필요):

1. `.venv/bin/python /usr/local/zed/get_python_api.py` — **휠 다운로드까지는 성공**한다. 그 뒤
   pip 설치 단계는 venv 에 pip 이 없어 실패하지만 무시해도 된다.
2. `uv pip install <받은 휠>`

휠 사본을 `~/.local/share/openarm/` 에 뒀다. 다음에 같은 일이 나면 1단계 없이 2단계만으로 된다.
