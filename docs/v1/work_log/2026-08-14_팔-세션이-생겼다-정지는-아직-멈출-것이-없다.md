# 2026-08-14 — 팔 세션이 `oa-serve` 안으로 들어왔다, 그리고 정지는 아직 멈출 것이 없다

앞 문서 `2026-08-14_배선-순서가-거꾸로였다.md` 가 남긴 다음 착수점 1번을 집었다. 그 문서가
*"올바른 순서는 팔 세션(래치의 주인) → 라우터 → GUI"* 라고 적어둔 대로 앞의 둘을 지었고,
**세 번째는 일부러 안 붙였다.** 이 문서는 왜 거기서 멈췄는지를 포함한다.

## 무엇이 생겼나

| | |
|---|---|
| `backend/actuation/session.py` | `ArmSession` — 래치 1개 · 팔당 보드 1개 · 리스 1개 · 틱 1개 |
| `backend/actuation/session_runner.py` | `ArmSessionRunner` — 커널 타이머로 틱을 도는 스레드 |
| `backend/config/arm.py` | `--arm` 이름을 세션으로 바꾸는 곳 (`none` 기본 · `dummy`) |

| `backend/config/serve.py` | 라우터가 **진짜로** 마운트된다, 세션이 있을 때만 |

`oa-serve --arm dummy` 로 실시간 소켓이 정확히 1개 뜨고, 관찰자 세션의 `stop_hold` 가 그
세션의 래치를 건다. `--arm none`(기본)은 예전과 완전히 같다.

## 🔴 래치는 아직 아무것도 멈추지 않는다 — 그래서 `STOP_HOLD_SENDER` 는 안 건드렸다

세션은 **읽고 게시할 뿐 보내지 않는다.** 버스 핸들도 engage 시퀀스도 없다. 그러므로:

- 정지는 귀속 가능하고(누가·언제) 해제 경로도 재무장 하나뿐이다 — 여기까지는 진짜다
- 그런데 **그 래치를 읽고 프레임을 멈출 루프가 이 프로세스에 없다**

이 상태에서 `frontend/src/app/backendLink.ts:20` 의 `STOP_HOLD_SENDER` 를 채우면 GUI 가
`{sent: true}` 를 받고 팔은 그대로다. `backendLink.ts:1-5` 가 이름으로 막아둔 것이고
(NORM-007), 앞 세션이 라우터를 먼저 붙이면 안 된다고 판단한 것과 **같은 이유**다. 순서가 한
칸 진전했을 뿐 마지막 칸의 조건은 그대로다: **명령하는 루프.**

`docs/v1/plan/02b-작업패키지-Wave-2-3.md:456` ⑥⑦ 중 ⑥(관찰자 `stop_hold` 수용 + 같은 세션
`command` 서버측 거부)은 이제 소켓을 통해 결함주입으로 확인된다
(`tests/wp3b15/test_arm_channel.py`). ⑦ 중 프로세스 재시작 항목은 사용자 결정(래치 메모리
전용)으로 미충족 상태 그대로다.

## 설계에서 두 번 방향이 바뀐 지점

### 팔은 둘인데 래치는 하나다

처음엔 `ArmSession` 이 보드 하나를 들었다. 배선하다 `contracts/prim/schema.py:97`
`ARM_SIDES = ("left", "right")` 에 부딪혔다. 수를 갈라야 했다:

- **래치 1개** — 정지는 리그에 대한 사실이다. 운영자가 "왼팔만 멈춰"를 뜻하는 경우는 없고,
  래치가 둘이면 기계의 절반만 서는 정지가 된다.
- **보드는 팔당 1개** — `ArmState` 에 side 차원이 없고, `board.py:21-22` 가 *"두 팔로워가 한
  프로세스를 공유하면 서로의 팔을 판정한다"* 고 이미 적어놨다.

두 번째 인스턴스가 이음매 위치를 알려준 사례다. 하나만 보고 지었으면 틀린 자리에 났다.

### 팔을 읽는 것을 인터페이스로 추상화하지 않았다

후보가 둘 있었다 — `OaOpenArmFollower`(`_poll_states` + `GuardSample`)와
`DummyOpenArmRobot`(`get_observation`, 48채널 flat dict). **오늘 둘은 같은 모양이 아니다.**
한 예시에서 이음매를 추측하면 아무 데도 안 맞는 추상이 나오므로, 읽기는 **호출 가능한 인자
하나**로 받는다. 새 타입 0개.

## `_poll_states` 가 torque 를 버리고 있었다

보드는 *"같은 프레임의 포즈와 토크"* 를 약속하는데 입력이 없었다.
`openarm_follower_oa.py:1066` 이 `position` 만 꺼내고 있었고, 벤더는
`sync_read_all_states` 로 셋을 **한 refresh 사이클에** 준다
(`.venv/.../lerobot/motors/damiao/damiao.py:660-666`). 추가 버스 트래픽 0.

변이 2종 다 잡힌다: `torque`→`velocity`(값은 그럴듯, 전부 0) · 포즈/토크 반환 순서 뒤집기.

## 코드 리뷰 14건 중 지금 경로 위의 것들

라우터를 마운트하면 Origin 검증기가 **살아있는 문**이 되므로 먼저 고쳤다. 근본 원인 하나 —
손으로 짠 URL 파싱:

| 입력 | 전 | 후 |
|---|---|---|
| `http://[::1]:8000` | 거부 (host=`'[::1]'`) | 수용 |
| `http://127.0.0.1:8000@evil.example` | **수용** (host=`'127.0.0.1'`) | 거부 (RFC 3986 §3.2 — 실제 host 는 `evil.example`) |
| `https://127.0.0.1:8000` | 거부 | 수용 |
| `ws://127.0.0.1:8000` | 수용 | 거부 — 브라우저는 Origin 에 `ws://` 를 절대 안 쓴다 |

두 번째가 실제 구멍이었다. 오늘 문이 아니었던 이유는 핸드셰이크가 정확 문자열 비교라서지
검증기가 옳아서가 아니다. `urllib.parse.urlsplit` 하나로 네 줄 다 닫힌다.

### 🔴 헤드라인 테스트가 아무것도 판정하지 않고 있었다

`test_the_loopback_deployment_can_actually_mount_the_route` 본문이 `pass` 였다. 거부된
핸드셰이크는 `accept()` **뒤에** 닫히므로 소켓 열기는 어느 쪽이든 성공한다 — 컨텍스트에
들어가기만 하는 테스트는 **아무도 수용 안 하는 서버에서도 통과한다.** 변이로 확인했다:
allowlist 를 `http://localhost:9999` 로 바꿔 4407 을 받게 해도 초록. 지금은 `stop_hold` 를
보내고 래치를 판정하며, 같은 변이에서 빨간불이다.

### 경계에서 실패하게 만든 것 둘

`backend/` 는 어느 mypy 게이트에도 없다(`scripts/gates.sh:33-38` 은 `registry ops dashboard`
와 `scripts` 만). 그래서 호스트가 넘기는 두 객체가 타입 검사를 안 받는다:

- 옛 `-> None` 계약으로 쓰인 sink 가 `bool` 을 반환하면 `outcome.closure.code` 에서
  **accept 뒤 소켓 안**에서 죽는다 → 브라우저는 코드 없는 끊김을 본다
- `admitted_origins` 가 "loopback 아님"을 "`.ws` 있음"으로 취급 → 첫 핸드셰이크에서
  `AttributeError`

둘 다 라우팅 지점에서 이름 있는 예외로 바꿨다. 이 모듈이 이미 쓰는 관용구다(`_envelope` 가
답장 필드를 `FRAME_TABLE` 과 대조해 raise 한다).

**참고로 전체 backend 를 mypy 게이트에 넣으면 274건/80파일이다.** 별도 작업이고 여기서 안 했다.

## 게이트가 내 테스트의 race 를 잡았다 — 2회차에서만

`tests/wp103/test_arm_session_runner.py::test_a_tick_that_raises_stops_the_loop_and_is_kept` 가
병렬 레인에서 간헐 실패했다. 원인은 **테스트 쪽 race**: `runner.start()` 직후 `runner.stop()`
이 첫 `tick()` 보다 먼저 플래그를 세우면 루프가 한 번도 안 돌고 나간다 — 이건 옳은 동작이고,
그러면 `failure` 가 None 이라 테스트가 아무것도 증명 못 한다. 실패하는 틱은 스레드를 스스로
끝내므로 `join` 으로 바꿨다.

같은 계열 둘 더 고쳤다: 대기 루프가 **busy-wait 라 GIL 을 쥐고 자기가 기다리는 틱 스레드를
굶겼다.** 병렬 레인은 이걸 24개 동시에 돌린다. 주기의 절반씩 sleep 하게 했다.

게이트 2회 연속 exit 0.
