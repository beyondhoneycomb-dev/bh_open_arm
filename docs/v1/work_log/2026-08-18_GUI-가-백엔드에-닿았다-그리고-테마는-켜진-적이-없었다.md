## WS 스택에 처음으로 호출자가 생겼다 (`4a81db1`)

`WsClient`·`LeaseRenewer`·우선순위 큐·디코드 워커가 전부 완성돼 있고 **그것을 만드는 코드가
0건**이었다(`createDefaultWsClient` 의 호출자 = 자기 정의뿐).

그런데 만들기만 해서는 서버가 안 받는다. `backend/ws/app.py` 의 핸드셰이크는 `role` 과
`session_id` 를 쿼리에서 읽고 없으면 닫는다(4400/4401). 그 거절이 **`accept()` 뒤에** 오므로,
파라미터 없이 붙는 클라이언트는 소켓을 열고 닫히며 — 운영자에게는 **백엔드가 죽은 것과 구별되지
않는다.** `resolveWsUrl` 은 둘 다 안 붙이고 있었다.

- `frontend/src/ws/handshakeUrl.ts` — 둘을 붙이고 `URLSearchParams` 로 인코딩한다. `&` 가 섞인
  session id 는 잘려 도착해 **열린 적 없는 세션에 정지를 귀속**시킨다(서버가 래치 사유를
  `gui-stop:<session_id>` 로 적는다). 빈 session id 는 소켓을 열기 전에 거부한다.
- 기본 역할은 **observer**. operator 로 붙으면 페이지를 여는 것만으로 단일 제어권 리스를 가져간다.
- `frontend/src/app/RealtimeContext.tsx` — 라우터 **바깥**에 있다. D-2 가 실시간 소켓 하나만
  허용하는데 라우터 안에 두면 화면을 옮길 때마다 다시 지어지고, 두 번째 실시간 경로는 두 번째
  정지 경로다(`WP-3B-15` ⑤ FAIL_BLOCKING). `useState` 초기화로 한 번만 짓는 것이 그 보장을
  규칙이 아니라 **구조**로 만든다.
- status 가 2값인 이유: 소켓이 열려 조용한 것과 아예 못 지어진 것은 데이터로 똑같이 보인다(빈
  리스, 텔레메트리 없음). 못 지었는데 `open` 이라 말하면 화면이 붙지도 않은 리그를 idle 로 그린다.

## 리스가 화면에 뜬다 — `src/mode/` 1,514줄이 처음으로 렌더된다 (`e08f686`)

`ControlLeaseView` 가 셸 크롬에 붙어 살아있는 스냅샷을 그린다. 리스 상태(session_id ·
generation · sequence · 데드맨 잔여)가 모든 화면 상단에 산다.

붙이면서 **두 트리 사이가 안 맞는 것**을 발견했다:

- 서버가 보내는 거절 사유 **6개**(`frontend/src/ws/envelope.ts` `LEASE_REJECT_REASONS`)
- 뷰가 라벨하는 verdict **5개**(`frontend/src/mode/lease.ts` `LeaseVerdict`)
- 같은 것은 **3개**뿐

`rejected_latched` · `rejected_unarmed` · `rejected_unknown_generation` 은 라벨이 없다. 없는 것을
있는 라벨에 억지로 넣으면 거짓말이 된다 — 특히 **`rejected_latched` 를 "재생 공격"으로 그리면
운영자가 걷어야 할 래치 대신 있지도 않은 두 번째 클라이언트를 찾으러 간다.** 매핑되는 셋만
매핑하고 나머지는 서버 원문을 그대로 띄운다(`frontend/src/app/leaseView.ts`).

두 가지를 더 구별한다:

- **리스 없음 vs 채널 없음** — 데이터로는 둘 다 빈 리스인데, 하나만 "물어보면 제어권을 받을 수
  있는" 상태다. 채널 부재는 자기 줄을 갖는다.
- **expiry 없음 = 리스 없음** — 0 을 넣으면 시간의 시작에 만료된 리스로 그려지고, 그건 "제어권을
  잃었다"로 읽히는데 실제로는 가진 적이 없다.

## 🔴 테마 토글이 13화면 전부에서 아무 일도 안 하고 있었다 (`9eb3a03`)

`Layout.tsx` 가 `data-theme` 을 셸 **`<div>`** 에 찍는데, 그것을 읽는 CSS 는 전부
`:root[data-theme="dark"]` 로 쓰여 있다. **`:root` 는 `<html>` 이다.** 속성과 셀렉터가 만난 적이
없다.

앞 세션 기록에 *"11/13 화면이 무시"* 라 적었는데 **틀렸다 — 되는 화면이 0개였다.** S-04·S-11 이
`data-theme` 을 읽긴 하지만 그 셀렉터가 죽어 있었다.

고친 것:

- `frontend/src/app/documentTheme.tsx` — 선택을 `<html>` 에 쓴다. `system` 은 **아무것도 안 쓴다**
  (그게 OS 가 결정하라는 뜻이고, 속성을 쓰면 이미 있는 두 답 위에 세 번째 답을 얹는 것이 된다).
  속성은 React 가 소유하지 않는 노드에 있으므로 언마운트에서 지운다.
- 화면 CSS 를 **양방향**으로. 명시 dark 블록만 더하면 "명시 light + OS dark" 가 여전히 어둡다.
  미디어 블록에 `:root:not([data-theme="light"])` 가드를 걸고 명시 dark 를 더한다.
  대상: `S-01`·`S-02`·`S-06`·`S-10`·`S-12`.
- 🔴 `app/shell.css` 와 `global/safety.css` 는 셀렉터가 `:root` **자신**이라 스크립트가
  `:root:not(...) :root` 라는 말이 안 되는 후손 셀렉터를 만들었다. 되돌리고 손으로 고쳤다 —
  **이 둘이 전 화면에 걸린다.**
- S-04·S-11 은 명시 light 블록으로 이미 같은 결과를 내므로(특이도가 미디어 블록을 이긴다)
  건드리지 않았다.

**CSS 는 테스트가 안 잡는다.** 그래서 번들을 실제로 빌드해 확인했다 — 명시 dark 규칙 17개,
가드 15개가 살아 있다(미니파이어가 따옴표만 뗀다).
