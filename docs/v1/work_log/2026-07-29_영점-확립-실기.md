# 2026-07-29 — 양팔 영점 확립 (실기, 24V)

## 절차 (`02` FR-CON-063 순서 그대로)

토크 OFF 확인 → 사람이 손으로 자세 정렬 → 전 모터 0xFD(토크 해제) → 1.5초 정착 →
모터별 0xFE → readback → 잔차 검증 → 원자적 영속.

`0xFE` 는 팔당 **7개 모터에만** 갔다 — 그리퍼가 없으므로 `0x08` 은 부르지 않았다
(`EndEffectorProfile.motor_send_ids`). 없는 모터에 보내면 무응답 프레임이 쌓여 컨트롤러가
ERROR-PASSIVE 로 떨어지고 실재하는 관절까지 열화된다.

**`lerobot-calibrate` 는 호출하지 않았다.** `Q-10` 이 (a) 를 택한 이유가 이것이다 — 그 명령은
영점을 잡으면서 동시에 전 관절 리밋을 ±90° 로 하드코딩해 버린다(`openarm_follower.py:201`,
*"Setting range: -90° to +90° for safety by default for all joints"*, 가동범위 스캔 없음).

## 결과

| | 왼팔(can0) | 오른팔(can1) |
|---|---|---|
| 0xFE 대상 | 7모터 | 7모터 |
| readback 원시값 | 전 관절 **32767** | 전 관절 **32767** |
| 잔차 | **0.0109도** | **0.0109도** |
| 허용치 ±0.5도 | 통과 | 통과 |
| 전원 재인가 후 | **변화 없음 (0.0109도 유지)** | **변화 없음** |

🔴 **0.0109도는 반 LSB 이며, 이 하드웨어가 표현할 수 있는 가장 정확한 0 이다.**
16비트 위치의 1 LSB = 2×12.5rad/65535 = 0.0219도이고, 중앙값 32767.5 에 가장 가까운 정수가
32767 이다. 일곱 관절이 모두 같은 값을 보이는 것은 디코드 오류가 아니라 전부 정확히 영점에
있다는 뜻이며, 원시 바이트(`017fff…`, `047fff…`, `077fff…`)로 직접 확인했다.

## 영점 자세 = 늘어뜨린 자세임을 계산으로 확인

명세 `03`:333 이 *"lerobot 의 hanging 자세는 URDF 영점이 아니다"* 라고 경고하지만, 그 경고의
대상은 **자세가 아니라 `lerobot-calibrate` 가 같이 저지르는 리밋 하드코딩**이다. 자세 자체는
FK 로 확인했다 (`sim.ik.adapter.build_ik_adapter`, MJCF 월드, m):

| 자세 | 손끝 z |
|---|---|
| **q = 0 (영점)** | **0.904** ← 가장 낮음 |
| J4 = π/2 (홈) | 1.120 |
| J2 = π/2 | 1.340 |

`q=0` 에서 좌우가 y = ±0.1535 로 대칭이고 z 가 가장 낮다 — 몸통 옆에 나란히 내려온 자세다.
즉 이 로봇에서 **늘어뜨린 자세 = URDF 영점**이고, `zero_method=lerobot_hanging` 은 정확한 기록이다.

## 정렬 과정에서 배운 것

첫 읽기에서 왼팔 J3 가 +89.3도, J5 가 −80.6도로 나왔다. 이는 팔이 이상한 자세라는 뜻이 아니라
**이전 영점이 좌우 다르게 잡혀 있었다**는 뜻이다 — 읽히는 각도는 마지막 0xFE 자세 기준이므로,
영점을 잡으려고 각도를 보는 것은 순환이다. 그래서 `FR-CON-063` 이 *"기준 자세 이미지 + 모달
확인"* 을 요구한다: 숫자가 아니라 사람이 눈으로 본다.

사람이 자세를 맞춘 뒤 9초 동안 흘러내림을 측정해 최대 0.02도로 정지했음을 확인하고 나서 쳤다.
브레이크가 없으므로 흘러내리는 중에 치면 그 흘러내린 자리가 영원한 영점이 된다.

## 산출물 위치

- 캘리브레이션 정본: `~/.config/openarm/calibration/openarm_{left,right}.oa_cal.json`
  (`CTR-CAL@v2` 스키마, 체크섬 포함, 원자적 쓰기)
- 캡처 사본: `~/openarm_captures/calib/`

저장소에 두지 않는다 — 이 값은 **이 리그의 이 모터들**에 대한 사실이고, 다른 기계가 받아서
쓰면 틀린다. `02` §2.0.4 의 디스크 SoT 패턴 그대로다.

## 이 단계에서 열린 것

영점이 잡혔으므로 관절각이 이제 의미를 갖는다. 이후 단계(그리퍼 엔드포인트 — 현재 구성에는
해당 없음, 홈 복귀, 충돌 임계값 보정, 마찰 식별)가 전부 이 좌표계 위에서 돈다.

`zero_power_cycle_verified=True` 이므로 세션마다 재영점할 필요가 없다
(`require_rezero_each_session=False`).
