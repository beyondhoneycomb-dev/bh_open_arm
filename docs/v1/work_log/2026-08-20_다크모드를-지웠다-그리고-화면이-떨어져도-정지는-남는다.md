## 1. 다크 모드를 지웠다 — 사용자 확정

사용자 확정: *"다크 모드는 그냥 안 할거야. 만약 있으면 있는 것도 없애."*

### 이것이 명세를 건드리지 않는 이유

`docs/v1/spec/`·`docs/v1/plan/` 전체에서 테마를 요구하는 FR/NFR 은 **0건**이다. `FR-GUI-004`
(`13`:172)가 영속을 요구하는 대상은 *"패널/뷰 레이아웃과 사용자 프리셋"* 이고 테마가 아니다.
`theme` 서브객체는 명세가 요구하지 않은 채 구현이 스스로 발행한 것이었고, 다크가 사라지면 값이
하나뿐이 되는 설정 knob 이 된다. 그래서 블록만 지우지 않고 **서브객체째** 지웠다.

### 지운 것

| 층 | 무엇 |
|---|---|
| CSS 9파일 | `@media (prefers-color-scheme: dark)` 블록과 `:root[data-theme="dark"]` 블록 전량. `S-04`·`S-11` 은 `[data-theme="light"]` 블록도 함께 지우되 **S-11 은 토큰을 base `.oa-inf` 규칙으로 올렸다** — 그 파일은 light 값을 그 블록에만 두고 있었다 |
| 셸 | `frontend/src/app/documentTheme.tsx` + 그 테스트 삭제, `Layout.tsx` 의 `<DocumentTheme>` 제거 |
| 프런트 설정 | `frontend/src/config/schema.ts` 의 `ThemeMode`·`ThemeConfig`·`THEME_SPEC` |
| 백엔드 설정 | `backend/config/` 의 `ThemeConfig`·`SUBOBJECT_THEME`·`ThemeMode`·`THEME_MODE_DEFAULT`·`FIELD_MODE` |
| 주석 | 8파일이 *"inherit the viewer's light/dark theme"* 라 적고 있었다. 거짓이 된 문장이라 고쳤다 |

`runtime_config` 서브객체는 5개에서 4개(`layout`·`presets`·`endEffector`·`control`)가 됐다.

### 디스크에 남은 `theme` 키는 마이그레이션이 필요 없다

`backend/config/model.py` `parse_document` 의 계약이 그것을 이미 정했다 — *"A top-level key
outside `SUBOBJECT_KEYS` is dropped rather than refused"*. 기존 `runtime_config.json` 에 남은
`theme` 는 조용히 버려지고, 나머지 서브객체는 그대로 산다. `extra="forbid"` 가 문서 전체를
거절하는 경로가 아니다.

### 대가

OS 가 다크인 운영자에게 앱은 이제 밝게만 뜬다. 리그가 어두운 셀에 있으면 눈이 부시다.
되살리려면 토글(약 60줄)과 지금 지운 CSS 블록을 다시 써야 한다.
**뒤집히는 조건**: 운영자가 실제 리그 조명에서 밝은 UI 를 못 읽겠다고 하거나, 어두운 셀에
상시 표시용 디스플레이가 붙을 때.

### 옮겨 심은 테스트 픽스처

`theme` 는 blast-radius 격리(`CG-G-00d`)의 시연 대상이기도 했다 — "한 서브객체가 malformed 면
그것만 defaults" 를 보이는 데 쓰였다. 그 자리를 `control` 이 받았다(`controlTickHz` 가
10–200 Hz 밴드를 벗어나면 거절되므로 malformed 를 만들기 쉽다). 격리 자체는 그대로 검사된다.

## 2. 화면이 떨어져도 정지는 남는다 — `ScreenErrorBoundary`

전 트리에 `ErrorBoundary` 가 **0건**이었다. 모든 화면과 뷰포트는 lazy 청크로 온다
(`routes/screenResolver.ts`, `app/ViewportRoute.tsx`). 청크 로드 실패는 promise 로 돌아오지 않고
**렌더 중에 throw** 하므로, 경계가 없으면 그 throw 가 트리 전체를 되감는다 — 배포로 번들 해시가
바뀐 뒤 열려 있던 탭이 그 라우트로 가면 **안전 바까지 통째로 사라진다.** `CG-G-03b` 는 전
라우트에서 STOP_HOLD 도달을 요구하는데, 언마운트된 문서는 어느 라우트에서도 그것을 못 준다.

`frontend/src/app/ScreenErrorBoundary.tsx` 를 `Layout.tsx` 의 outlet 슬롯 안, `SafetyBarHost`
**아래**에 넣었다. 화면 결함의 폭발 반경이 패널 하나로 줄어든다.

### 헤더 주석이 이미 그 속성을 주장하고 있었다

`Layout.tsx` 파일 머리말은 전부터 이렇게 적혀 있었다 — *"no route, redirect, or screen error
can replace it"*. **그 문장을 집행하는 것이 아무것도 없었다.** 형제 배치는 라우트 교체와
리다이렉트는 막지만 throw 는 못 막는다 — throw 는 형제까지 함께 되감기 때문이다. 주석이 코드보다
앞서 있었고, 이 커밋이 뒤늦게 코드를 주석에 맞춘 것이다.

### 새로고침 버튼은 안 만들었다

nav 레일이 그대로 살아 있고 그것이 복구 경로다. 새로고침은 WS 세션을 끝내므로 제어 리스가
끊기고 데드맨이 래치된다 — 안전한 방향이긴 하지만 **로봇 상태 변경**이고, 이 패널은 그것을
운영자에게 묻는 자리가 아니다.

### `key={pathname}` 은 취향이 아니다

React 는 경계의 에러 상태를 컴포넌트가 교체될 때까지 들고 있다. 키가 없으면 **처음 실패한 청크
하나가 그 뒤 운영자가 고르는 모든 라우트를 빈 화면으로 만든다** — nav 레일이 복구 경로가 된 바로
그 순간에 복구 경로이기를 그만둔다. 변이 검사로 확인했다: `key` 만 떼면 4개 중 리셋 테스트
1개가 정확히 죽는다.

## 3. 모드 권한표가 처음으로 렌더된다

`ModeAuthorityTable` 은 프로덕션 호출자가 0이었다(`mode/index.ts` 의 export 뿐). 셸 크롬의
리스 표면 옆에 접힌 `<details>` 로 붙였다 — 8행 표를 모든 화면에 펼쳐 두는 것은 비싸고,
라우트는 13 + `/viewport` 로 동결(`CG-G-00b`)이라 전용 라우트를 만들 수 없다.

### `activeMode` 를 `ModeId | null` 로 넓혔다

프롭이 `ModeId` 필수였다. 그러면 붙이는 쪽이 **모드 하나를 골라야 하고**, 표시된 행은
"리그가 이 모드다" 로 읽힌다. 이 빌드는 모드를 관측하지 않는다 — `StatusBadgeBar` 가 이미
`data-badge="mode"` 를 "미상"으로 그리는 이유가 그것이다. 타입이 "모른다"를 표현하지 못해서
붙이는 쪽이 거짓말을 하게 되는 구조였고, 그것을 넓혔다. 지금은 `null` 을 넘겨 **아무 행도
표시하지 않는다.**

`src/mode/**` 에는 스타일시트가 없다. 표가 셸 크롬에서 무제한으로 넓어지지 않도록
`app/shell.css` 에 최소 스타일을 넣었다(마운트하는 쪽이 WP-G-00 이므로 그 트리에).

## 5. 🔴 텔레메트리 publisher 는 `CTR-WS@v3` 를 연다 — 여기서 멈췄다

`ArmStateBoard` 는 틱마다 쓰이는데 `board.view()` 의 프로덕션 소비자가 **0건**이다. 보드가
허공에 게시한다. 이것을 닫으려면 서버가 `telemetry` 프레임을 보내야 하고, 거기서 막혔다.

**`CTR-WS@v2` 의 프레임 표에 `telemetry` 의 필드가 없다.** 양쪽 다 비어 있다:

- `contracts/ws/schema.py` `FRAME_TABLE[TELEMETRY].fields = ()`
- `frontend/src/ws/envelope.ts` `FRAME_TABLE.telemetry.fields = []`

그리고 `backend/ws/dispatch.py` `_envelope` 는 본문 필드 집합이 표와 **정확히 일치하지 않으면
raise** 한다. 프런트 쪽은 `envelope.contract.test.ts:87` 이 동결 사본과 대조한다.

`06` §4.3 이 이 상황의 규칙을 이미 못 박았다:

> **동결 후 어떤 필드 추가도 `@v(n+1)`이다.** 선택이든 필수든 구분하지 않는다 — 구분선이

## 5b. 리뷰가 잡은 것 — 게이트 스크래치 빌드가 소스 트리를 지울 수 있었다

`/code-review` 가 6건을 냈고 전부 직접 확인했다. 하나가 진짜 위험했다.

### 🔴 `mktemp -d` 가 실패하면 게이트가 `frontend/` 를 비운다

이 스크립트는 `set -e` 가 없어서 `GATE_BUNDLE_DIR="$(mktemp -d)"` 의 종료코드를 아무도 안 봤다.
mktemp 이 실패하면 변수는 unset 이 아니라 **빈 문자열**이 되고 다음 줄이
`vite build --outDir "" --emptyOutDir` 가 된다. 실측했다 — vite 는 이것을 **경고로만** 처리한다:

```
(!) build.outDir must not be the same directory of root or a parent directory of root
    as this could cause Vite to overwriting source files with build outputs.
```

경고 뒤에 계속 진행하고 `--emptyOutDir` 가 `frontend/` 를 비운다. 뒤따르는 `rm -rf ""` 는
no-op 이라 아무것도 막지 않는다. **디스크가 찬 날 게이트를 돌리면 `src/` 가 사라진다.**

`if GATE_BUNDLE_DIR="$(mktemp -d)" && [ -n "$GATE_BUNDLE_DIR" ]` 로 가드했다. 실패 경로는
빌드를 건너뛰고 `FAILED` 에 올린다 — 조용히 초록이 되지 않는다. mktemp 을 실패하게 만들어
검증했다: 빌드 미실행, `FAILED` 등재, `frontend/src` 무사.

### 게이트가 dist 를 안 건드리게 됐으니, 낡은 dist 를 알려줄 것이 필요하다

`oa-serve` 는 `frontend/dist/index.html` 존재 여부만 보고 마운트한다 — 신선도는 안 본다.
지금 이 트리의 `frontend/dist/assets/` CSS 8개에 **이번에 지운 `prefers-color-scheme` 이 그대로
살아 있다**(00:05 빌드본). 게이트가 초록인 채로 `oa-serve` 를 띄우면 다크 CSS 와 에러 경계 없는
변경 전 번들이 아무 신호 없이 서빙된다.

`spa_bundle_built_at()` 을 만들어 기동 줄에 `SPA bundle: <경로> (built <시각>)` 을 찍는다.
자동 판정은 안 한다 — 신선도 규칙을 백엔드가 발명하면 그것이 또 하나의 정본이 된다. 시각만
보여주고 판단은 운영자가 한다.

### `color-scheme: light` 가 빠져 있었다

다크 CSS 를 지웠는데 브라우저는 여전히 OS 선호를 따른다. 페이지에 네이티브 컨트롤이 74개
있고(`checkbox`·`range`·`select`·`input`) 스크롤바까지, **흰 배경 위에 어둡게 그려진다.**
`:root { color-scheme: light; }` 한 줄로 닫았다. 이것은 다크를 되살리는 것이 아니라 그 반대다 —
페이지가 light 하나뿐이라고 브라우저에 말해주는 것이다.

### 닫힌 `<details>` 안을 조회하던 테스트

jsdom 은 닫힌 `details` 의 자식을 숨기지 않는다. 실제 브라우저는 렌더도 접근성 트리 진입도
안 한다. 즉 "전 라우트에서 8행 표가 뜬다"는 주장이 **disclosure 가 영구히 안 열리게 깨져도
초록**이었다. summary 를 클릭한 뒤 조회하도록 고쳤다.

### 주석이 검사하지 않는 것을 주장했다

`EndEffectorPanel.test.tsx` 에서 테마 픽스처를 걷다가 *"layout and presets never appear"* 로
문구를 고쳤는데 단언은 layout 하나뿐이었다. 형제를 이름으로 세는 대신 **endEffector 이외의
어떤 서브객체 경로로도 PUT 이 안 나간다**로 바꿨다 — 서브객체가 늘거나 줄어도 규칙을 계속 덮는다.

### 하나는 안 고쳤다

권한표 `<details>` 가 에러 경계 **위**에 있다는 지적. 맞다. 다만 그것은 동결 상수 배열을
map 하고 바깥에서 아무 입력도 안 받아 throw 할 분기가 없고, 경계 아래로 내리면 **화면이
죽었을 때 "무엇이 아직 명령할 수 있나"를 보는 참조가 같이 사라진다.** 그 이유를 `Layout.tsx`
주석에 박았다.

## 6b. 🔴 백엔드 결함이 브라우저에 닿은 뒤 버려진다

`NotificationCenter` 를 "데이터원 0" 으로 적었는데 **틀렸다. 원천은 이미 도착하고 있다.**

- `frontend/src/ws/wsClient.ts:362-364` — `case "error": this.mErrorCount += 1;
  this.mCallbacks.onError?.(frame.error); return;`
- `frontend/src/ws/defaults.ts` `createDefaultWsClient` 가 `onError` 를 **안 넘긴다**
- `frontend/src/app/App.tsx:24` 도 오버라이드를 안 준다

그래서 `OA-*` 에러 프레임은 `stats().errorCount` 에 숫자로만 쌓이고 **내용은 사라진다.**
`NotificationBadge` 는 이미 전 화면에 떠 있지만(`StatusBadgeBar.tsx:100`) 받는 배열이
`SafetyBarHost.tsx:50` 의 `NO_SESSION_NOTIFICATIONS = []` 상수라 영구히 `경고 0` 이다.

**즉 `CG-G-03g`(ERROR 이상은 ack 전까지 배지 유지)를 만족시킬 수 있는 상태가 이 빌드에서는
발생할 수 없다.**

계약 변경은 필요 없다. `ErrorEnvelope{code, reason, severity}`(`ws/errors.ts`)에서
`Notification{id, code, severity, source, timestamp, detail, acked}`
(`global/notifications.ts:10-21`)로 가는 사상은 전부 채울 수 있다 —
`source` 는 `oaDomainOf(code)`, `detail` 은 `reason`, `severity` 는 `SEVERITY_LEVELS[…]`.

**판단이 필요한 것 하나**: `timestamp` 다. 봉투에 서버 시각이 없어 **브라우저 수신 시각**밖에
쓸 것이 없고, 그러면 그 값은 "사건이 난 시각"이 아니라 "우리가 안 시각"이다. 화면이 그것을
사건 시각으로 그리면 또 하나의 거짓이 된다. 사상 자체는 열려 있으나 이 한 줄은 결정 사항이라
이번 회차에서 착수하지 않았다.

### 실측 — 진입점 도달성

진입점 14개(`pyproject` 콘솔 스크립트 8 + `scripts/*.py` 5 + `ops.launch.cli`)에서 `import` 를
이행적으로 따라갔다:

```
1급 파이썬 모듈 1,080개 · 164,544줄
  도달   249개 ·  47,441줄  (29%)
  미도달 831개 · 117,103줄  (71%)
```

**7할이 아무 실행 경로에도 안 걸린다.** 그런데 거기에도 테스트가 붙어 있고 게이트가 초록이다.
초록불이 "된다"가 아니라 "안 도는 코드가 자기 테스트를 통과했다"는 뜻이었다.

### 가장 선명한 증상 — 카메라 스택이 둘

| | 줄수 | 진입점 |
|---|---|---|
| `backend/camera/**` | 2,806 | `oa-camcap` 이 쓴다 |
| `backend/sensing/**` | 7,772 | **없다** |

`WP-3B-01`~`06` 이 시킨 대로 `sensing` 을 지었는데, 실기 카메라를 실제로 열어야 했을 때 아무도 그

`sensing/bandwidth/spec.py:7` 이 대역폭 산식의 정본을 `backend.camera.bandwidth` 라고 적어놨다.

같은 양식이 하나 더 있다: `backend/loadtest/constants.py:30-31` 이 WS 발행율 정본(30/60 Hz)을
쥐고 있는데 그 트리는 도달 불가이고, 정작 `backend/ws/` 에는 그 상수가 0건이다. **필요한 조각이
안 쓰는 상자에 갇혀 있다.**

진단: 명세 단위로 상자를 지었고 **상자끼리 안 이었다.** 그래서 상자가 크고, 다음 사람은 상자를

## 9. 이 회차에 에이전트 dispatch

정찰 3개 + 리뷰 4개 + `/code-review` 포크 1개를 띄웠고 **8개 전부 보고했다.**

`2026-08-18` 인계 §0-③ 은 *"에이전트 dispatch 가 이 환경에서 안 돈다"* 라고 적었고 나도 그
판정을 이어받아 세션 중간에 "무응답"이라고 두 번 적었다. **둘 다 틀렸다 — 느린 것이었다.**
정찰 셋은 약 15분, 리뷰 넷은 약 18분 걸렸고 포크만 7분이었다. 그 사이 나는 직접 파일을 열어
같은 일을 했으므로 결과는 중복됐지만, **늦게 온 보고가 내가 놓친 것을 셋 냈다**:

| 어디서 | 내가 놓친 것 |
|---|---|
| `/code-review` 포크 | §5b 의 `mktemp` — 게이트가 소스 트리를 지울 수 있는 경로 |
| 정찰(telemetry) | `envelope.schema.json` 동결 사본 + `CI-09` · S-03 이 이미 읽고 있는 미선언 본문 · `expect_close()` 가 요청 없는 프레임에 깨진다는 것 |
| 정찰(ui) | **`onError` 가 안 배선돼 결함 프레임이 버려진다**(§6b) — 내 "데이터원 0" 판정을 뒤집었다 |

**교훈은 "에이전트가 안 돈다"가 아니라 "기다리지 말고 병행하되 버리지도 말라"다.** 15분 뒤에
오는 보고를 없는 셈 치면 이번처럼 판정 하나가 틀린 채로 남는다.
