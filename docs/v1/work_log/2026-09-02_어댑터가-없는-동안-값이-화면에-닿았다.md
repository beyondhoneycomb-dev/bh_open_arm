# 2026-09-02 — 어댑터가 없는 동안 값이 화면에 닿았다

PCAN 어댑터를 다른 사람이 쓰고 있다. 그동안 어댑터 없이 되는 것을 전부 진행했다.

하드웨어 현황: PCAN 없음(`can3` 만 유령으로 UP) · Arducam 2대 빠짐 · ZED-M 은 붙어 있다
(`/dev/video0,1`). 그래서 `--arm real` 은 못 띄웠고, 검증은 `--arm dummy` 와 `--arm none`
실서버 + 게이트로 했다.

커밋 넷: `604180a` `d9e2c7e` `973a519` `a2cbf18`.

## 1. 어제 커밋이 남긴 결함 둘

### 발행율 정본이 셋이 됐다

`NFR-GUI-003` 과 `FR-GUI-022` 는 둘 다 [확정]이고 기본 30 Hz / 상한 60 Hz 다
(`spec/13`:195,344). 그 숫자는 `frontend/src/viewport/constants.ts:24-25` 와
`backend/loadtest/constants.py:30-31` 에 이미 있었는데, 어제 내가 실제로 발행하는 쪽인
`backend/ws/app.py:123` 에 `DEFAULT_TELEMETRY_HZ = 20.0` 을 새로 박았다. 명세가 정한 값을
**서버만 안 읽는** 상태였다.

숫자를 `backend/ws/constants.py` 로 옮겼다 — 그 값으로 실제로 도는 루프가 거기 있다.
`loadtest` 는 이제 owner 를 import 한다. `loadtest/constants.py` 의 "프런트가 런타임
governor 를 소유한다"는 주석도 고쳤다: 프런트의 `resolvePublishRate` 는 *요청*을 검사하고,
보내는 것은 이 루프다.

### 죽은 읽기 루프가 도는 동안에는 아무 데도 안 보였다

전날 관찰: 어댑터가 USB EPROTO 로 빠진 뒤 45분간 화면 배지가 "연결됨"이었다. 사슬을
소스에서 확인했다.

1. `session_runner.py:78-83` — tick 이 raise 하면 `self.failure` 에 넣고 **return**.
2. 그 필드를 읽는 곳은 `serve.py:501` 하나뿐이고 그건 **uvicorn 이 끝난 뒤**다.
3. `ws/app.py` 의 `_push_telemetry` 는 계속 `board.view()` 를 떠서 보낸다. `board.py:170`
   이 마지막 state 를 영원히 돌려주므로 45분 전 값이 초당 30번 나갔다.
4. 프레임 자체는 정직했다 — `read_age_s` 는 자라고 `tick_index` 는 얼어붙는다.
   **읽는 쪽이 안 봤다**: `SafetyBarHost.tsx` 의 배지가 `arms.length` 만 셌다.

두 층에서 고쳤다.

- **runner**: 죽는 그 자리에서 stderr 로 말한다. 예외를 필드에 담아두는 것은 보고가 아니다.
  문장은 예외뿐 아니라 결과도 적는다 — "보드가 여기서부터 안 움직인다"는 예외 텍스트가
  말해주지 않는다.
- **프레임**: `arms` 행에 `stale` 이 생겼다. 나이를 판정하는 데 필요한 tick 주기는 이
  프로세스만 알고 브라우저는 모른다. 마감은 `mount_websocket_router` 가 실제
  `control_tick_hz` × `TELEMETRY_STALE_TICK_MULTIPLE`(5)로 계산한다.
- **배지**: 연결됨의 뜻이 "프레임이 온다"에서 "읽기가 전진한다"로 바뀌었다. 한쪽 팔만 얼면
  반대쪽은 계속 연결됨. 배지만으로는 "세션 없음"과 "얼었음"을 못 가르므로 얼었을 때는 알림
  줄을 따로 낸다 — 둘은 운영자에게 정반대를 요구한다.

판정은 나이 하나로 한다. `ArmStateView.is_driving_blind` 가 두 사실을 요구하는 것과 다른데,
여기엔 idle 이 없기 때문이다 — 보드를 채우는 runner 는 살아있는 한 무조건 틱한다.

## 2. 관절이 프레임에 올라갔다

`S-04` 는 관절 표를 그리는데 그릴 것이 픽스처뿐이었다. 프레임의 48채널 observation 벡터는
정책이 먹는 LeRobot 이름·단위이고, 화면이 필요한 것은 URDF 이름·라디안·그리고 자기가 계산하면
안 되는 판정 둘이었다.

`joints` 절을 넣었다. 한 행이 관절 하나고, 열두 필드다.

- **이름 둘.** `name` 은 URDF/MJCF 관절, `motor` 는 LeRobot 채널 접두사. 두 namespace 사이의
  대응은 이 프로세스가 아는 사실이고 소비자는 못 만든다. 덕분에 `S-04` 가 `motor_states` 의
  온도를 붙이는 것이 문자열 수술이 아니라 lookup 이다.
- **단위 둘.** `deg` 는 버스가 답한 값, `rad` 는 `contracts.units` 의 그 한 번의 crossing 을
  통과한 값. 브라우저는 변환하면 안 된다(`jointSnapshot.ts` 가 명시한다).
- **리밋이 값과 같이 간다.** 안 변하는 숫자를 30 Hz 로 보내는 건 낭비로 보이지만, 아래 판정이
  바로 그 리밋에서 나온 것이다. 따로 받아둔 사본을 든 클라이언트는 다른 설정에서 온 경계에
  대고 근접 경고를 그릴 수 있다.
- **판정 둘.** `04` FR-MAN-013 — 여유 5° 아래면 `near_limit`, 경계에 닿으면 그 방향만
  `blocked`. `backend/jog/proximity.py` 가 순수함수로 들고 있다. 소프트셋 밖에 주차된 관절은
  나가는 방향만 막고 돌아오는 방향은 연다 — 둘 다 막으면 푸는 데 버스 세션과 육각렌치가 필요하다.

프레임 크기는 16행에 약 7.4 kB, 30 Hz 면 약 220 kB/s. 백프레셔 임계
(`BUFFERED_AMOUNT_THRESHOLD_BYTES` = 1 MiB) 대비 142프레임 여유.

### `S-04` 배선에서 걸린 것

`screen.tsx` 를 라우트로 만들고 화면을 `ManualScreen.tsx` 로 옮겼다(S-03 과 같은 모양).
살아난 것은 관절 표 전부 + 온도 + 스트림 나이다.

문제는 **섞임**이었다. 나머지 필드를 픽스처로 두면 실기 관절값 옆에 그럴듯한 값이 선다.
필드별로 갈랐다:

- **EE 포즈** — 운영자가 측정값으로 읽을 유일한 필드다. 채널이 없으므로 여섯 성분을 null 로
  보내고 패널이 대시를 그린다. `EeReadout` 의 타입을 nullable 로 바꿨다.
- **온도** — 같은 이유로 nullable. 온도계 없는 리더의 0 ℃ 는 어는 모터로 읽힌다.
- **IK 파라미터·게인 프로파일·홈/티치 목록** — 설정 모양이라 이 리그의 측정으로 오해되지
  않는다. 오프라인 기본값 그대로 두고 라우트 주석에 무엇이 살아있고 무엇이 아닌지 적었다.

`RealtimeProvider` 가 프레임 도착 시각(`telemetryAtMs`)을 같이 든다. 그건 콜백만 아는
사실이고, 화면이 렌더 시각으로 재면 자기 재렌더를 재는 것이 된다.

## 3. `S-13` 이 부르던 백엔드

`/api/system/report` 는 프런트가 이미 부르고 있었고 그 자리에 아무것도 없었다.
`createDefaultSource` 가 이미 그 경로를 fetch 하므로 **프런트는 손댈 게 없었다** —
바꾼 건 nullable 두 개와 그걸 그리는 자리뿐이다.

### 포트 정본을 어디서 읽는가

STATUS 가 적어둔 문제: 정본이 `spec/01` §2.17 마크다운 표뿐이라 상수로 박으면 세 번째
정본이 된다. `CLAUDE.md` §4b 가 답을 갖고 있었다 — *"한 사실이 두 곳에 있어야 할 때,
둘을 비교하는 테스트 하나가 진짜 드리프트를 잡는다."*

`contracts/ports/port_map.yaml` 에 기계 판독형을 두고, 미러 테스트가 `01` §2.17 과
`14` §2.1 두 표에서 포트를 정규식으로 긁어 집합 비교한다. **이름으로 비교하지 않는다** —
두 표가 같은 것을 다르게 부른다("웹 백엔드 (SPA 정적 + REST + WebSocket)" vs "브라우저 SPA ↔
GUI 백엔드"). 표가 합의하는 것은 숫자고, 비교 화면이 다루는 것도 숫자다.

미러 테스트에 "표에서 5행 이상 찾았는가"를 같이 넣었다. 헤딩이 움직이면 빈 집합 둘을
비교하면서 일치한다고 보고하기 때문이다.

`served_by_this_process` 를 한 행에 표시한다. 비교 화면(`portCompare.ts:40`)이 실제 바인딩을
정본과 **이름으로** 맞추므로 서버가 자기 행 이름을 알아야 한다. 포트로 유도하면 `--port` 가
움직이는 순간 깨지는데, 그건 그 화면이 보여주려는 바로 그 경우다.

### 호스트를 읽는다

`psutil` 이 없다. `/proc` 을 직접 읽는다 — 명세(`14` FR-OPS-023)가 지목한 증거가 그거다.

- **실제 바인딩**: `/proc/net/tcp` + `tcp6`. v4 만 읽으면 `::` 에 붙은 서버를 못 봐서 없는
  충돌을 만든다. 소유자는 `/proc/<pid>/fd` 라 남의 프로세스는 못 읽고 그건 `unknown` 으로
  간다. 데스크톱에 리스닝 소켓이 77개인데 이 리그의 컴포넌트는 하나도 없으므로, **선언된
  포트 위의 것과 이 프로세스가 쥔 것만** 남긴다. 남이 웹 백엔드 포트에 앉아 있으면 그건
  그대로 보인다.
- **RT 자세**: `os.sched_get*` 과 `/proc/<pid>/status` 의 VmLck. 못 읽은 VmLck 는 null 이지
  0 이 아니다 — 0 은 "mlockall 이 아무것도 안 잠갔다"는 실측이다.
- **`mlockallReturnedOk` 는 null 이다.** 이 저장소는 mlockall 을 안 부른다. `false` 는
  syscall 이 실패했다는 말이고 그건 안 불렀다는 것과 다른 사실이다. `rtCheck.ts` 의
  "조용한 실패" 판정도 `=== true` 로 좁혔다 — 안 부른 프로세스마다 빨간 줄이 서면 안 된다.

판정 하나만 붙인다: 어느 프로세스도 RT 정책을 안 가지면 `OA-SYS-003`. 실제로 이 호스트가
그렇고, 그래서 그 검사는 오늘 데이터에서 빨갛다.

번들 매니페스트는 이 리포트가 **실제로 실은** 두 항목(`system_info`·`bound_port_map`)만
주장한다. 원클릭 생성기가 없는데 항목을 주장하면 없는 능력을 주장하는 것이다.

실서버 확인: `--port 8124` 로 띄우니 actual 이 8124 를 정본 이름으로 잡고 정본 8000 과
어긋나는 것을 그대로 보고한다.

## 4. 뷰포트 — 포즈는 왔고 모델은 없다

`latestFrame` 이 영구히 null 이었다. stream-age 는 언제나 stale 이었고 그 stale 은 스트림에
대해 아무 말도 안 했다.

이제 텔레메트리로 짓는다. 수용 게이트(CG-G-02d)와 stream-age 규칙(CG-G-02e, 정지 시 제어입력
차단)이 실제 데이터 위에서 돈다.

**관절 집합이 서로 다르다.** 버스는 그리퍼 포함 16개를 보고하고 모델은 14개를 선언한다.
선언된 것만 가져간다 — 게이트를 푼 게 아니다. 게이트가 잡으라는 것은 "모델에 있는데 프레임에
없는 관절"이고 그건 그대로 missing 으로 도착해 거절된다. 없어지는 것은 `unexpected-joint`
분기인데, 그건 URDF 가 안 가진 그리퍼에 대고 매 프레임 발화하던 것이다.

**모델은 아직 없다.** `openarm_description` 은 이 저장소에도 이 기계에도 없다(찾아봤다).
`robotHandle` 은 null 이고 캔버스는 씬만 그린다. 자산 필드를 채우는 건 없는 파일에
provenance 배너를 다는 일이라 안 했다. 벤더링 여부는 결정 사항으로 STATUS §8 에 올렸다.

`useLiveViewportSource` 는 자기 모듈이다. `/viewport` 라우트와 뷰포트를 끼워 넣는 화면들이
같은 걸 부른다 — 프레임 하나에 빌더 둘이 임베드와 라우트를 두 개의 뷰포트로 갈라놓는
방식이고, WP-G-02 의 공개 표면이 막으려던 게 그거다.

## 6. 남긴 것

- **정지 명령 루프** — 어댑터가 돌아와야 한다. 사람이 팔 옆에 있어야 하는 항목.
- **뷰포트 모델 자산** — 외부 저장소 벤더링 결정.
- **`S-04` 팔 선택기** — 두 팔이 wire 에 다 있는데 화면이 하나만 그린다. 화면 변경.
- **EE 포즈 채널** — FK 를 어디서 돌릴 것인가.
- `backend/loadtest/harness.py` 의 `TELEMETRY_FRAME_BYTES = 2048` 은 이제 실제 프레임보다
  3.6배 작다. 부하 모델 값이고 카메라 클래스가 3~4자릿수 크므로 결과를 안 움직인다 —
  고치지 않았고, 여기 적어둔다.
