# 2026-08-04 — ZED SDK 설치 준비 (내려받기·검증·플래그 결정)

🔴 **이 문서 시점에 설치는 아직 실행되지 않았다.** 설치기는 root 로 실행하면 안 되고 스스로
sudo 를 요청하는데 이 호스트는 무암호 sudo 가 안 되므로, 실행은 조작자 몫이다. 여기 적힌 것은
**무엇을 왜 고를지 정하고 그 근거를 실측한 데까지**다.

## 왜 필요한가

`backend/sensing/depth/reverify.py:160` 의 `real_depth_supported` 가 세 가지를 따로 본다:

| 차단 사유 | 상태 |
|---|---|
| ① `pyzed` 미설치 | **SDK 설치가 해소한다** |
| ② LeRobot 에 `stereolabs_zed` 카메라 클래스 없음 | **SDK 를 깔아도 안 해소된다** — 아래 참조 |
| ③ USB 링크에 비디오 인터페이스 없음 | 이미 해소됨 (`2b03:f682`, 5000 Mbps) |

②가 남는 이유는 `backend/sensing/depth/constants.py` 의
`LEROBOT_DEPTH_CAMERA_CLASS[STEREOLABS_ZED] = None` 이다. LeRobot v0.6.0 의 카메라 백엔드는
`opencv`·`reachy2_camera`·`realsense`·`zmq` 뿐이고 ZED 는 없다. 명세가 이미 그렇게 정해뒀다 —
`01-시스템-아키텍처.md:405`: *"ZED은 LeRobot 표준 카메라 클래스에 없으므로 **서드파티 커스텀
경로(선택)** 로만 다룬다."*

즉 **SDK 설치와 카메라 클래스 작성은 별개의 두 일**이고, 이 문서는 앞의 것만 다룬다
(사용자 지시: *"일단 sdk 설치만 해, 적용은 나중에 할거야"*).

## 버전 선정 — URL 을 직접 두드려서

ZED SDK **5.4** 가 최신이다. Stereolabs 는 예측 가능한 다운로드 URL 규약을 쓰므로 후보를 직접
확인했다:

| URL | 크기 | 판정 |
|---|---|---|
| `zedsdk/5.4/cu13/ubuntu24` | 1,632,180,715 | ✅ **선택** — CUDA 13, 우리가 13.2 |
| `zedsdk/5.4/cu12/ubuntu24` | 1,419,030,975 | CUDA 12 빌드 |
| `zedsdk/5.4/cu126/ubuntu24` | 306,306 | ❌ **실재하지 않음** — 306 KB 는 오류 페이지다 |
| `zedsdk/5.3/cu12/ubuntu24` | 1,418,693,628 | 구버전 |

🔴 **`cu126` 은 HTTP 200 을 돌려준다.** 상태 코드만 봤으면 유효한 설치기로 판정했을 것이다.
크기를 같이 봐야 오류 페이지와 구별된다 — 200 은 "서버가 답했다"이지 "그것이 설치기다"가 아니다.

## 설치기를 실행하지 않고 뜯어봤다

Makeself 헤더에서 실제 실행되는 스크립트 이름을 읽고(`script="./linux_install_release.sh"`),
페이로드에서 그 파일만 꺼냈다(1,371줄).

```bash
tail -c 1632161831 ZED_SDK_*.run | zstd -dc | tar xO ./linux_install_release.sh
```

### 받는 인자 (107–134행)

`--silent` · `--skip_tools` · `--skip_cuda` · `--skip_od_module` · `--skip_python` ·
`--skip_drivers`

### 확인한 동작 두 가지

**CUDA (2행, 274행)** — `REQUIRED_CUDA_VERSION=13.0` 이고 주석이 *"The ZED SDK accepts any CUDA
${cuda_major}.x"* 라고 적는다. 우리 13.2 는 major 13 이므로 맞다.

**파이썬 (1230–1251행)** — 설치기가 **시스템 `python3` 에** `pip install` 하며, pip 23 이상이면
`--break-system-packages` 를 붙인다:

```bash
pip_flags="--break-system-packages"
${python3_exe} -m pip install numpy $pip_flags
${python3_exe} -m pip install requests $pip_flags
${python3_exe} "${installation_folder}/get_python_api.py" $force_flag
```

Ubuntu 24.04 의 `python3` 은 PEP 668 관리 대상이고, 이 저장소 코드는 `.venv`(python 3.12.13,
numpy 2.2.6)에서 돈다. 설치기에 맡기면 **필요 없는 곳을 오염시키고 필요한 곳에는 안 들어간다.**

**root 실행 금지 (971행)** — *"This script shouldn't be run as root, the root permission will be
asked when needed"*. `sudo ./ZED_SDK_*.run` 이 아니라 그냥 실행해야 하고, 설치기가 필요할 때
스스로 묻는다.

## 결정한 명령

```bash
/…/scratchpad/ZED_SDK_ubuntu24_cu13.run --silent --skip_cuda --skip_python
```

| 플래그 | 근거 |
|---|---|
| `--skip_cuda` | CUDA 13.2 가 이미 있고 설치기가 그것을 받아들인다. 빼면 기존 툴킷을 건드릴 수 있다 |
| `--skip_python` | 시스템 파이썬 오염 회피. 설치 후 `.venv` 로 직접 넣는다 |
| 도구는 남김 | ZED Explorer·Depth Viewer 는 깊이가 실제로 나오는지 우리 코드 밖에서 독립 확인하는 수단이다 |

**설치될 것**: `/usr/local/zed`, apt 의존성 13개(`libusb-1.0-0`, `libopenblas-dev`, `libv4l-0`,
`mesa-utils`, `libarchive-dev`, `libjpeg-turbo8` 등), Qt5 도구 스택, udev 규칙 2개
(`99-slabs.rules`, `60-zed-buffers.conf`).

## 남은 순서

1. **설치 실행** — 조작자가 위 명령을 돌린다(암호 1회, 5~10분)
2. **`pyzed` 를 `.venv` 로** — `/usr/local/zed/get_python_api.py` 를 `.venv` 파이썬으로 실행.
   이 단계는 sudo 가 필요 없다
3. **실기 확인** — 실제 ZED 로 깊이 프레임이 나오는지. 이때까지는 ① 만 해소된 상태다
4. **카메라 클래스** — ②를 해소하려면 `Camera` ABC 6개(`is_connected`·`find_cameras`·`connect`·
   `read`·`async_read`·`disconnect`)와 깊이 API 3개(`read_depth`·`async_read_depth`·
   `read_latest_depth`)를 갖춘 클래스를 써서 `LEROBOT_DEPTH_CAMERA_CLASS` 가 그것을 가리키게
   해야 한다. `version_gate.py:63` 의 `depth_record_api_present` 가 뒤의 둘을 `hasattr` 로 본다.
   **사용자 지시로 보류** — 적용은 나중에 한다
