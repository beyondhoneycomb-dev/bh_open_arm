## Why

### 1. `Q-10` 은 닫혔다 — (a) 다. 늘어뜨린 자세가 URDF 영점이다

무토크 판독만으로는 못 닫는다. **영점을 그 자세에서 잡았으니 그 자세가 0으로 읽히는 것은
순환 논증이다.** 순환이 아닌 증거는 URDF 기하에서만 나온다.

우리 자산(`sim/mjcf/v2/openarm_bimanual.xml`)을 `qpos = 0` 으로 놓고 FK 를 돌렸다:

```
오른팔 체인, qpos = 0
  link2  x=+0.0000  y=-0.1535  z= 0.0000
  link3  x=+0.0000  y=-0.1535  z=-0.0663
  link4  x=+0.0000  y=-0.1535  z=-0.2200      x 는 전 링크 0 고정
  link5  x=+0.0000  y=-0.1535  z=-0.3155      y 는 link2 이후 상수
  link6  x=+0.0000  y=-0.1535  z=-0.4360      z 만 단조 하강
  손끝   x=-0.0014  y=-0.1715  z=-0.5040
```

**수직 낙하다.** link1→ee_base 벡터가 수직에서 7.836° 벗어나 있는데 그 전부가 어깨 y 오프셋
0.06 m 이고 관절각이 아니다(모든 링크의 y 가 같다).

그리고 MJCF 의 오른팔 관절 범위 7/7 이 명세 §2.9 의 URDF 원본과 **정확히** 일치한다
(J1 `[-1.3963, +3.4907]` … J7 `[±1.5708]`). 즉 이 자산의 q=0 은 URDF 의 q=0 이다.
왼팔은 J1·J2 가 반사돼 있어 `FR-MOT-035` 미러 규칙도 자산에서 성립한다.

실기 무토크 판독(14/14, 0xFD 만):

```
왼팔  J1 +6.02  J2 -0.80  J3 -10.94  J4 +15.27  J5 +15.42  J6 -4.99  J7 -4.67
오른팔 J1 -0.80  J2 +1.10  J3 +10.55  J4  +2.50  J5  -1.52  J6 -3.60  J7 -8.36
```

전부 영점 ±16° 안. 두 증거가 같은 답을 가리킨다 — 옆 레포 실측(`offset` 전부 0)과도 같다.

🔴 **남은 정직한 단서 하나**: 왼팔 J4 +15.27° / J5 +15.42° 는 옆 레포가 보고한
`|q_raw| < 10°` 보다 크다. 팔이 자유롭게 늘어져 있으므로 중력 처짐으로 설명되지만,
**"쉬는 자세"가 반복 가능한 자세는 아니라는 뜻**이기도 하다. 영점의 정확도는 그만큼 열려 있다.
프레임 판정(a)은 이것과 무관하게 성립한다.

### 2. 버스 실측 — 옆 레포 D3 와 같은 답

`bh_remy_openArm` `docs/decisions.md` D3 가 batch 전송을 실측으로 확정했다. 우리 리그에서
같은 것을 쟀다(300 사이클, 무토크 0xFD 만):

| | remy (16모터) | **우리 (14모터)** |
|---|---|---|
| sequential | 4.74 ms · max 6.93 | 4.24 ms · max 6.17 |
| **batch** | 3.06 ms · max 3.34 | **2.71 ms · max 3.16** |
| 달성 | 326 Hz | **369 Hz** |
| 유실 | 0/4800 | **0/4200** |

batch 가 1.56배 빠르고 **지터가 절반**(max 3.16 vs 6.17)이다. 제어 루프에서는 후자가 더
중요하다 — D3 의 판단과 같다. 100 Hz 틱이면 IO 가 예산의 27%.

### 3. 🔴 슬립은 주기를 쥘 수 없다 — 세 방식을 실제 버스에서 쟀다

`sleep(period - work)` 이 주기를 못 쥐는 이유는 산수가 틀려서가 아니다. **실제 주기가
`work + sleep` 이고 `work` 항이 구조적으로 변한다.** 200프레임, 20 Hz, 실제 CAN:

| | p50 | p99 | max |
|---|---|---|---|
| 오늘 조그 (`exchange` + `sleep(period)`) | 50.493 | 50.845 | 50.851 |
| `sleep(period − work)` | 50.067 | 50.229 | 50.260 |
| **커널 타이머** | **50.000** | **50.148** | **50.149** |

오늘 조그는 매 프레임 0.49 ms 느렸다. 그 자체는 1% 지만 **오차가 work 에 비례한다**:
프레임 하나가 무응답이면 `REPLY_TIMEOUT_S = 50 ms` 가 통째로 더해져 주기가 두 배가 된다.

**그리고 MIT 에서 주기가 늘어난 채 setpoint 가 계획대로 전진하면 그건 토크가 틀리는 것이다** —
모터는 `kp·(q_des − q)` 로 답한다. 옆 Indy7 리그가 눈에 보이는 저크의 원인으로 지목한 것이
같은 것이고, 그쪽 해법도 이것이다(`docs/spatula/work_log/2026-08-11_the-camera-was-setting-the-command-rate.md`).

### 4. 놓친 주기는 세고, 버린다

타이머가 자기 만료를 세므로 **초과는 침묵이 아니라 숫자**다. 그리고 놓친 만료는
**되쏘지 않고 버린다** — 밀린 프레임을 몰아 보내면 누적된 setpoint 전진이 전선에 한 스텝으로
나가고, 그게 정확히 pacing 이 막으려는 토크 스파이크다. 호출자에게는 몇 개를 잃었는지만 준다.

조그가 끝에 그것을 말한다:
```
주기 50.0 ms · 프레임 100개 · 초과 0
```
프레임별 오차 줄로는 이걸 볼 수 없기 때문에 따로 적는다 — 주기가 걸어도 관절은 잘 따라간다.
다만 계획보다 느린 램프를 따라가는 것이고, 화면의 다른 어떤 줄도 그 말을 하지 않는다.

### 5. 🔴 바꾸면 안 되는 슬립 하나

`sim/harness/control_loop.py:206` 의 `time.sleep` 은 **그대로 둔다.** docstring 이 이유를
적어뒀다 — *"The wait uses `time.sleep`, which releases the GIL: the load thread runs during the
wait and, on wake, the victim must re-acquire the GIL — the exact point GIL contention delays
it."* 그건 LeRobot 의 루프 모양을 **일부러** 흉내내는 계측기(WP-0C-06 GIL 부하 하네스)다.
커널 타이머로 바꾸면 재려던 현상이 사라진다.

바꾼 것은 **실제 프레임을 전선에 태우는 pacing** 뿐이다.

변이 중 **`닫힌 pacer 가 대기` 는 처음에 0건이었다.** `close()` 가 `_fd = -1` 로 두므로
`os.read(-1, …)` 이 어차피 `OSError(EBADF)` 를 내고 그것이 `PacerError` 로 감싸이기 때문이다.
즉 가드는 예외를 만드는 게 아니라 **진단 문구만** 만든다. 테스트가 문구를 검사하게 바꾸니
잡혔다. 가드가 값을 하는 지점을 테스트가 못 보고 있었다.

## Follow-ups

- **`can_node_watch.py:874` · `canbind_session.py:513` 도 `sleep(remaining)` 이다.** 둘 다
  setpoint 를 전진시키지 않는 폴링이라 토크가 되지는 않지만, 응답률 산술(`610 시도 / 15 s`)이
  주기에 의존하므로 계측 정확도에는 걸린다. 이번엔 안 건드렸다.
- **단일 제어 스레드 + 블랙보드는 아직 붙일 곳이 없다.** `ActuationScheduler.tick()` 은 있으나
  그것을 도는 루프가 없다(메모리의 "컴포넌트 검증 ≠ 어셈블리 검증"). 지금 블랙보드를 지으면
  호출자 0인 코어가 하나 더 생긴다 — 다음 착수점인 **여러 관절 동시 명령**이 그 루프이고,
  거기서 레퍼런스 모양(단일 버스 소유 · 틱당 1회 batch 읽기 · 프레임 스왑 보드 ·
  `commanded_since_read` 를 함께 보는 staleness)으로 처음부터 짓는 것이 맞다.
- 옆 레포 `ArmStateBoard` 와 `bh_remy_openArm` D6 은 같은 이름의 서로 다른 물건이다: 전자는
  **락 없는 프로즌 객체 스왑**, 후자는 **단일 coarse lock + 깊은 복사**. 전자가 최신이고 안전
  스레드의 비용이 속성 읽기 하나다. 우리 것은 전자를 따른다.
