**뿌리가 다르다.** 우리 상수는 전부 *"이 관절이 무엇을 견디나"* 에서 왔다 — `URDF_EFFORT_LIMIT_NM`
주석이 스스로 적었듯 *"effort equals peak torque exactly"*. 저쪽 것은 *"무엇이 실제로 부서졌나"*
에서 왔다. 40 N·m 는 URDF 가 적은 수고, 1.86 N·m 는 그리퍼가 두 번 부서진 수다.

손목 캡은 특히 나쁘다 — 722 는 실측 폭주(162)의 4.5배라 **가드로 작동하지 않는다.** 어깨 캡 90 은
반대로 정상 동작보다 낮아 **오탐한다.** 양쪽 끝이 다 틀렸다.

### 🔴 CAN 상한 계산이 반증됐다

우리 `NFR-SYS-002` / `NFR-PRF-001` `[확정]`: 32프레임 ≈ 1600 µs → **625 Hz**.
저쪽 실측(`measure_latency.py`, 300 사이클, 유실 0/4800): **3.06 ms → 326 Hz**. 정확히 **1.9배**.

이유가 적혀 있다 — 8모터 16프레임의 이론 전송시간이 1 Mbps 에서 **133 µs** 인데 실측 **1.53 ms
로 11배**다. **지배 항이 대역폭이 아니라 모터 응답 처리 + 커널/유저 왕복이다.**

파급이 숫자 하나보다 크다: `NFR-PRF-001`(`15:418`)은 프레임당 50 µs 선로시간으로 계산하는
**예산 계산기**이고 100%에서 설정을 거부한다. 선로시간이 실비용의 1/11 이므로 **그 게이트는
리그가 못 도는 설정을 통과시킨다.**

### 🔴 우리 명세에 없는 실패 양식 — 게이트가 폭주를 만든다

```
push8   충돌 거부 131 틱 연속 → 거부가 풀리는 순간  1280.2 °/s

```
> **폭주 다섯이 게이트 리밋 초과가 있던 다섯과 정확히 일치했다 — 리밋 초과가 원인, 폭주가 증상.**

거부가 N틱 유지되다 풀리면 IK 가 그동안 벌어진 간격을 **한 틱에** 메운다.
**우리 거부-후-재개 경로 전부가 이 구조다** — 충돌 게이트, 속도 리미터, 워크스페이스 박스,
그리고 `guard.py` 의 래치.

**이 세션에서 내가 두 번 틀렸다.** 처음엔 문서를 믿고 실제를 안 쟀고(래치가 급하다고 판정),
