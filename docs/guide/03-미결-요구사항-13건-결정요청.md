# 결정 1 — 충돌 임계값 기본치 `FR-SAF-020`

> ### ❓ effort 리밋의 **0.1배**를 충돌 임계값 기본으로 유지할까?
> **`[4.0, 4.0, 2.7, 2.7, 0.7, 0.7, 0.7]` Nm** (관절별 effort `40/40/27/27/7/7/7` Nm의 0.1배)

**지금 코드**: 그렇게 돼 있다 — `backend/threshold/constants.py:44` `THRESHOLD_DEFAULT_NM`.

**뭐가 갈렸나**: 이 숫자는 **논문에서 유도한 이론값이지 OpenArm 실측이 아니다.**
근거 논문(PMC7805958)이 말하는 건 *"정상 동작 최대/최소를 5~10% 초과하는 경계"* 라는 일반 규칙뿐이다.
그래서 "이걸 기본으로 써도 되나, 아니면 실측 전까지 기본값을 안 주나"가 갈렸다.

| | |
|---|---|
| **유지하면** | 임계값이 있어서 충돌 감지가 동작한다. 대신 UI에 *"이론적 출발점이며 실측 검증값 아님"* 을 반드시 표시해야 한다(명세가 요구) |
| **바꾸면** | 실측 전까지 충돌 감지에 기본 임계값이 없다 = 사실상 못 쓴다 |

**내 추천: 예(유지).** 임계값 없이는 기능 자체가 안 돌고, 명세가 이미 "실측 아님" 표시를 의무화해서
이 값이 검증된 것처럼 인용되는 걸 막아뒀다.

# 결정 7 — 1 kHz 목표를 625 Hz 아래로 내리기 `NFR-SAF-001`

> ### ❓ 충돌 감지 루프 목표를 **1 kHz → 625 Hz 상한 아래**로 내리는 것에 동의하나?

**뭐가 갈렸나**: 명세 원문은 충돌 감지 루프를 **1 kHz(주기 1 ms)** 로 요구한다. 그런데 **물리적으로 불가능하다.**

계산이 확정돼 있다:

| | |
|---|---|
| LeRobot 한 사이클 | `get_observation()`(refresh 라운드) + `send_action()`(MIT 라운드) = **32 CAN 프레임** |

| 500 Hz면 | 버스 부하 **80%** |
| 1000 Hz면 | **불가** |

명세 본문은 이미 `[개정 2026-07-15, B7]` 로 *"1 kHz는 CAN 프레임 예산에 종속, 1000 Hz는 물리적
불가"* 라고 고쳐져 있다. **형식상 확인만 필요한 셈이다.**

## `CI-07`이 정확히 뭘 요구하나

원장(`docs/v1/plan/normalization/ledger.yaml`)의 한 행이 곧 하나의 판정이다. 행에는 **어느 읽기가
이기고 어느 텍스트가 폐기됐는지**가 구조화된 필드로 들어간다. 원장 스키마에 **"미결" 상태는 없다** —
행이 있으면 판정된 것이고, 없으면 미결이다.

그래서 B 분류(결정 6·7)도 *"값은 M-8 실측에 위임하고, 그때까지 어떤 목표 주파수도 합격 기준으로
쓰지 않는다"* 라는 **판정**으로 기록하면 정상적으로 닫힌다. 숫자를 지어낼 필요가 없다.

지금 1,216개 레코드 중 판정 해시를 가진 건 14개다.
