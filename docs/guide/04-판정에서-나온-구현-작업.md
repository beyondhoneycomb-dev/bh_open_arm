## 1. 충돌 임계값을 운영자가 바꾸고, 저장되게 (NORM-009)

**지금**: `backend/threshold/constants.py:44` 에 `THRESHOLD_DEFAULT_NM` 상수만 있다.
바꾸는 경로도, 저장하는 경로도 **없다**(검색 결과 0건).

**필요한 것**
- 관절별 임계값을 운영자가 설정할 수 있어야 한다
- 설정한 값이 디스크에 저장되어 **재기동 후에도 유지**되어야 한다
- 기본값(0.1 × effort)은 그대로 두되, 저장된 값이 있으면 그것이 이긴다

**주의**: 기존 상한·하한 검사는 그대로 살아 있어야 한다.
아래 `backend/threshold/constants.py` 가 이미 강제하는 것들이다.

| 경계 | 값 | 왜 |
|---|---|---|
| 하한 | 토크 12비트 최소단위 × 10 (`0.264 / 0.137 / 0.049` Nm) | 이보다 낮으면 센서 분해능 밑이라 양자화 잡음에 반응한다 |
| 상한 | 관절 effort 리밋 (`40/40/27/27/7/7/7` Nm) | 이보다 높으면 절대 못 넘어 그 관절 감지가 죽는다 |

운영자가 이 범위 밖 값을 넣으면 **거부**해야 한다.

**소유**: `WP-2C-03`(임계값 보정)

## 2. GUI에 "비교 대상은 잔차"임을 명시 (NORM-009)

**지금**: 프론트엔드에 잔차 관련 문구가 **없다**.

**왜 필요한가**: 임계값 4 Nm 를 "모터 토크가 4 Nm 넘으면 정지"로 읽으면 완전히 틀린다.
팔을 뻗고 가만히 있기만 해도 중력을 이기느라 어깨에 수십 Nm 가 걸린다 — 그 읽기라면
팔이 아예 못 움직인다.

실제 비교 대상은 **잔차**다:

```
잔차 = 실제 관절 토크 − (중력 + 마찰 + 관성으로 설명되는 토크)
```

아무 일 없으면 0 근처이고, 외부에서 밀릴 때만 올라간다. 코드로는
`backend/gmo/isolation.py:60-61` 에서 `np.abs(잔차) >= 임계값` 으로 비교한다.

**필요한 것**: 임계값 설정 화면의 문안이 이 구분을 분명히 할 것. "관절에 걸리는 토크"가
아니라 "설명되지 않는 외부 토크"임이 읽는 사람에게 전달되어야 한다.

**소유**: `WP-G-S12`(안전 화면)

## 3. 관측기 이득 K를 운영자가 바꾸고, 저장되게 (NORM-011)

**지금**: `backend/gmo/constants.py:34` 에 `DEFAULT_OBSERVER_GAIN = 90.0` 상수만 있다.

**필요한 것**: 1번과 같은 형태 — 설정 가능 + 재기동 후 유지.

**🔴 함께 걸어야 하는 검사**: K 를 바꾸면 **감지 루프 주기 조건도 같이 바뀐다.**

관측기는 매 주기 `적분 += (beta + 잔차) × dt` 로 도는 전진 오일러 적분이라
(`backend/gmo/observer.py:118`), **`K × dt < 2` 에서만 수렴**한다. 넘으면 발산한다.

| K | 필요한 루프 | 넘으면 |
|---|---|---|
| 90 (기본) | 45 Hz 초과 | 10 Hz 에서 잔차가 45 → −315 → 2565 → −20475 로 발산 |
| 180 | 90 Hz 초과 | |
| 45 | 22.5 Hz 초과 | |

운영자가 K 를 올리면 **현재 루프 주기로 수렴 가능한지 검사하고, 안 되면 거부**해야 한다.
발산하면 임계값이 매 주기 넘어가서 아무 일 없어도 계속 충돌로 뜬다 — 감지가 안 되는 게
아니라 못 쓰게 된다.

**소유**: `WP-2C-03`

## 4. 충돌 감지 루프 목표를 100 Hz로 (NORM-008)

**지금**: `backend/gmo/constants.py:41` 이 명목 주기를 **1 kHz** 로 두고 있다.

**필요한 것**: 100 Hz 로 내린다.

**왜 1 kHz 가 아닌가**: 한 사이클에 CAN 프레임이 32개 나가서 CAN-FD 상한이 625 Hz 다.
1 kHz 는 물리적으로 불가능하다.

**왜 10 Hz 가 아닌가**: 3번의 수렴 조건 때문이다. K=90 에 10 Hz 면 `K × dt = 9` 로 발산한다.
100 Hz 면 `K × dt = 0.9` 로 3주기(30 ms)에 수렴한다.

**이건 합격선이 아니다.** 어떤 주파수도 통과/실패 판정에 쓰지 않기로 했다(NORM-008).
100 Hz 는 잔차 기반 감지가 **성립하는 조건**이지 게이트가 아니다.

**소유**: `WP-2C-02`(GMO 잔차)

## 5. 주파수를 게이트에서 빼고, 계측해서 GUI에 표시 (NORM-008)

**지금**: `backend/rtbench/fmax.py:122` 의 `enforce_target_hz(target_hz, fmax)` 가
목표 주파수를 상한과 비교해 강제한다.

**필요한 것**
- 주파수 값이 **통과/실패 판정에 쓰이는 경로를 없앤다**
- 대신 실측치(중간값·상위 5%·상위 1%·최대, 주기 초과 비율)를 **계측해서 GUI에 표시**한다
- 운영자가 "지금 몇 Hz로 돌고 있는지" 화면에서 볼 수 있어야 한다

**남기는 것**: 4번의 `K × dt < 2` 검사는 게이트가 아니라 기능 성립 조건이므로 유지한다.

**소유**: `WP-1-04`(실시간 측정), 표시는 `WP-5-05`

## 6. 녹화 fps를 운영자가 조절 가능하게 (NORM-013)

**지금**: `backend/recorder/embed/session.py:125` 가 `spec.fps` 를 받아 쓰지만,
운영자가 바꾸는 경로가 **없다**.

**필요한 것**: 녹화 시작 전에 fps 를 고를 수 있어야 한다.

**왜**: 녹화 레이트에 하한을 두지 않기로 했다(NORM-013). 하한이 없는 대신 **목표를 스스로
낮출 수 있어야** 측정이 의미를 갖는다 — 30 fps 를 못 따라가는 장비에서 30 을 고정해두면
"목표 미달"만 계속 쌓이고 아무도 손을 못 댄다.

**함께 유지**: 사이클 타임 분포(p50/p95/p99)와 목표 미달 프레임 비율 보고는 그대로.

**소유**: `WP-3B-12`(레코더 품질)

# 🔴 하나 남겨두는 위험 — 마찰 편향 (NORM-012)

v1 튜닝값을 기본 실행 파라미터로 쓰기로 했다. 근거는 그 값으로 VR 텔레오퍼레이션이
실제로 돈다는 관찰이다.

**남는 위험을 여기 적어둔다.** 텔레오퍼레이션이 도는 것과 마찰 파라미터가 v2 에 맞는 것은
다른 주장이다. 마찰값이 틀려도 텔레옵은 돈다 — 좀 뻑뻑하거나 무를 뿐이다.

문제는 **잔차가 마찰 추정을 빼서 만들어진다**는 점이다:

```
잔차 = 실제 토크 − (중력 + 마찰 + 관성)
                        ↑ 이게 틀리면
잔차에 편향이 남는다 → 1번의 임계값이 어긋난다
```

**그래서 재식별 전까지, 충돌 감지가 이상하면(헛뜀 또는 못 잡음) 이 편향을 먼저 의심한다.**
마찰 재식별은 실기 작업이다 — `docs/guide/02-실기-검증-무엇을-해야-하나.md` 4-4절
(`OPENARM_FRICTION_REAL_FIXTURE`).
