# 실기 검증 — 무엇을, 어떤 순서로, 누가 하나

이 문서는 **로봇 실물 앞에서 사람이 해야 하는 일**만 다룬다. 코드는 지금 오프라인으로 갈 수 있는
데까지 다 가 있고, 여기서부터는 **물건이 있어야 넘어간다.**

읽는 순서: 0장(지금 당장 막힌 것) → 1장(왜 당신이 해야 하나) → 2장(준비물) → 3장(순서) →
4장(항목별 상세) → 5장(하면 안 되는 것).

## 이 문서에서 쓰는 말

문서·코드에 이미 박혀 있는 말들이라 바꿀 수 없다. 뜻만 한 줄로 적어둔다.

| 말 | 뜻 |
|---|---|
| **게이트** | 통과 못 하면 그 아래 작업이 **코드 레벨에서 막히는** 검문소. 사람이 "됐다"고 넘길 수 없다. `PG-SAFE-001` 처럼 이름이 붙어 있다 |
| **리그(rig)** | 로봇 + 작업대 + 구속물 + 배선까지 합친 **실험 설비 한 벌**. "리그가 바뀌었다" = 그 중 뭐라도 옮겼다 |
| **페이로드** | 팔이 **들고 있는 물건**. 그리퍼에 잡힌 것, 손목에 붙인 것 전부 |
| **잔차** | 기대한 값과 실제로 잰 값의 **차이**. "잔차 ±0.5° 이내" = 오차가 0.5도를 넘지 않아야 한다 |
| **데드맨** | 사람이 **누르고 있는 동안만** 움직이게 하는 스위치. 손을 떼면 선다 |
| **오버런** | 제어 루프가 정해진 주기 안에 일을 **못 끝낸 횟수**. 500Hz면 2ms 안에 끝나야 하는데 넘긴 경우 |
| **p50 / p99** | 측정값을 줄 세웠을 때 **중간값 / 상위 1% 지점**. p99가 크면 "평소엔 빠른데 가끔 훅 느려진다"는 뜻 |
| **하드스톱** | 더 이상 안 돌아가게 **기계적으로 막아둔 끝지점** |
| **도달 포락(reach envelope)** | 팔이 **닿을 수 있는 공간 전체**. 구속물은 이 전체를 감싸야 한다 |
| **롤아웃** | 학습시킨 정책을 **실제 로봇에서 돌려보는 것** |
| **WP-… / FR-… / NFR-… / PG-… / CG-…** | 계획서·명세서의 **항목 번호**. WP=작업 단위, FR/NFR=요구사항, PG/CG=게이트 |

## 0. ✅ 전원 넣기 전에 고쳐야 했던 것 2가지 — 둘 다 끝났다

이 자리에 원래 "전원 넣기 전에는 시작하지 마라"는 항목 두 개가 있었다. **2026-07-28에 둘 다
닫혔다.** 기록으로 남긴다.

### 0-1. 좌우 팔이 뒤바뀌어 있었다 → 고쳤다 (`c73c2df`)

IK가 내놓는 16개 값은 `오른팔 8 + 왼팔 8` 순인데 우리 계약은 `왼팔 먼저`였고, 그 사이에 순서를
바꾸는 코드가 없었다. 결과적으로 안전 검사기가 **왼팔 값을 오른팔 한계로** 검사했고, 좌우 한계가
반대인 **2번 관절에서만 판정이 정확히 뒤집혔다.**

우리 코드를 전부 계약 순서(왼팔 먼저)로 통일하고, 상류 경계 **한 곳**에서만 변환한다
(`sim/ik/adapter.py`의 `_to_upstream_order`). 세 번째 순서를 만들지 않는 것이 요점이었다.
판별 테스트 `tests/wp0c09/test_arm_order_matches_the_action_contract.py`가 고치기 전 16/16 실패했다.

부수적으로 드러난 것: 재영점 위험을 재던 테스트가 고치기 전 **0 mm**를 재고 있었다(양팔 다 0).
고친 뒤 **43.2 mm**로 측정된다.

### 0-2. 뜻이 안 정해진 요구사항 13개 → 전부 판정하고 구현까지 끝냈다

사용자 판정을 원장(`docs/v1/plan/normalization/ledger.yaml`)에 `NORM-008`~`NORM-014` 7행으로
적재하고 해시를 재발행했다. 그 판정이 요구한 집행 9건도 코드로 들어갔다 —
자세한 것은 `docs/guide/04-판정에서-나온-구현-작업.md`와
`docs/v1/work_log/2026-07-28_판정-구현과-검사가-검사하지-않던-문제.md`.

판정 중 계산으로 잡은 모순 하나를 기록해 둔다: **관측기 이득 K=90과 감지 루프 10 Hz는 양립
불가능하다.** 관측기가 전진 오일러라 `K·dt < 2`에서만 수렴하는데 10 Hz면 `K·dt = 9`가 되어
잔차가 45 → −315 → 2565 → −20475로 발산한다. 감지 루프만 100 Hz(`K·dt = 0.9`)로 두는 안으로
해소했다. 이건 게이트가 아니라 **기능이 성립하는 조건**이다.

**즉 지금은 §2 준비물부터 시작하면 된다.** 코드 쪽 선행 조건은 없다.

## 1. 왜 이건 당신이 해야 하나

이 개발 PC에는 **로봇이 없다.** 확인된 사실:

- 가상 CAN(vcan) 인터페이스를 만들 수 없음 (비밀번호 없는 sudo가 안 됨)
- 카메라 없음, 모터 없음

**CAN 어댑터는 2026-07-29에 붙었다** (이 항목은 그전까지 "어댑터 없음"이었다). PEAK PCAN-USB Pro
FD(`0c72:0011`), `peak_usb` 드라이버 적재, `can0`·`can1` 2채널이 같은 USB 부모(`3-4:1.0`)에 붙은
**1개 듀얼채널 장치**, `clock 80000000`.

두 가지가 여기서 따라온다.

- **`ip link set`은 여전히 제가 못 칩니다.** 어댑터가 있어도 링크를 올리는 건 sudo라서 사람이
  칩니다. 안내서 05가 그런 명령에 `[당신이 직접]`을 붙여 표시한다.
- **어댑터가 1개라 채널이 2개다.** 계약 고정 이름은 4개(`oa_fl`/`oa_fr`/`oa_ll`/`oa_lr`)이고
  `FR-CON-005`는 **동일 VID/PID 어댑터 2개**를 전제한다. 팔로워 양팔 브링업에는 2채널로 충분하고,
  두 번째 어댑터는 텔레오퍼레이션(리더암) 단계에서 필요해진다. udev 2축 규칙의 어댑터축
  (`ATTRS{serial}` 또는 `KERNELS==`)이 둘을 구분해야 하므로, **§4-1의 udev 단계에 들어가기 전에
  두 번째 어댑터의 시리얼을 확보해 두는 편이 낫다.**

RTX 5080이 있어서 **시뮬레이션·학습·AI는 여기서 다 검증됐다.** 하지만 CAN 버스, 모터, 카메라는
물건이 있어야 한다.

### 역할 분담

| 제가 하는 것 | 당신만 할 수 있는 것 |
|---|---|
| 검사 프로그램(하네스) 작성·실행 | **물리 E-Stop 버튼 누르기** |
| 캡처한 데이터 자동 판정 | **전원 꺼진 팔을 손으로 잡아 자세 맞추기** |
| 로그·증거 정리 | **그리퍼를 물리적 끝까지 벌리고 닫아서 그 위치 캡처** |
| 수치 계산·통과/실패 판정 | **체커보드 들고 카메라 앞에서 움직이기** |
| 실패 시 원인 분석 | **팔이 떨어질 수 있는 구역 비우기, 구속물 설치** |
| — | **"이 자세가 안전한가" 최종 판단** |

계획 문서의 표현으로는 `Human-assisted-HW`(사람이 손을 대고 프로그램이 돈다)와
`Human-judgment`(최종 판정은 사람)다.

## 3. 순서

순서를 바꾸면 안 된다. 이유는 각 부에 적어뒀다.

```
[0장 코드 2건 해결]
        ↓
1부  물리 안전 게이트 (PG-SAFE-001)  ← 토크 켜기 전. 이거 통과 못 하면 아래 전부 차단
        ↓
2부  통신·모터 확인 (토크 계속 OFF)
        ↓
3부  영점 잡기 (토크 계속 OFF)
        ↓
4부  첫 토크 ON, 그리고 정지 성능
        ↓
5부  움직임 안전 (충돌·반응·마찰)
        ↓
6부  카메라·시간동기
        ↓
7부  텔레오퍼레이션
        ↓
8부  데이터 수집 → 학습 → 평가
```

### 1부 — 물리 안전 게이트: **이게 첫 관문이다**

프로젝트가 `PG-SAFE-001` 이라 부르는 것. 상세 절차는
`docs/v1/plan/04-리스크-및-안전-브링업-게이트.md` §4.3에 6요소(에이전트가 할 일 / 사람이 할 일 /
중단조건 / 안전 초기상태 / 산출증거 / 재개지점)로 다 적혀 있다. 여기서는 사람이 뭘 하는지만 정리한다.

**코드가 실제로 막고 있는 것과, 아직 확인 안 된 것을 구분해서 적는다.**

- 막고 있음(확인): 통과 기록이 없으면 토크 브링업이 **시작 자체를 거부**한다
  (`backend/torque_bringup/preconditions.py`). 5개 사전검사 중 하나라도 실패하면
  토크 인가가 거부된다(`backend/preflight/gate.py:49`).
- 🔴 **아직 확인 안 됨**: 이번 검토에서 *"검사기는 있는데 실제 실행 경로에 안 걸려 있는"* 사례가
  여러 건 나왔다. 예를 들어 충돌 래치를 갱신하는 함수가 **프로덕션에서 한 번도 호출되지 않아**
  충돌 판정이 항상 "충돌 없음"으로 고정돼 있다(미수정, 상세는 작업 로그 D-5).
  즉 **"게이트가 코드에 있다"와 "게이트가 실제 경로를 지킨다"는 다르다.**

→ 그래서 **소프트웨어 차단을 믿고 사람이 손을 떼면 안 된다.** 1부 전 단계에서 사람이 팔을
지지하는 이유가 이것이다. 진짜 안전장치는 물리 E-Stop 버튼과 구속물이다.

**들어가기 전 조건**: 정전·비상정지 후 복구 절차(RC-1~RC-5)가 **먼저 코드로 존재하고 검증돼야**
한다. 이유는 아래 5장에 있다.

| 단계 | 사람이 하는 일 | 무엇을 알아내나 | 중단해야 할 때 |
|---|---|---|---|
| **S-1** 전원 도메인 | 팔을 **전원 끈 채 손으로 잡고**, 지시에 따라 E-Stop 버튼을 누른다. **손을 떼지 않는다** | E-Stop이 모터 전원과 CAN을 **같이** 끊는지 | 눌러도 CAN 프레임이 계속 오면 → 중단. 호스트까지 꺼져 재부팅되면 → 중단 |
| **S-2** 기계적 구속 | **팔이 닿을 수 있는 공간 전체**를 막는 구속물을 설치하고, 그 구속물이 **몇 kg·몇 N 까지 버티는지 근거**를 문서로 남긴다 | 팔이 어디로도 못 나가는가 | 🔴 **시뮬레이션 결과는 이 단계의 증거가 아니다.** 막히지 않은 구간이 하나라도 남으면 실패 |
| **S-3** 낙하영역 | 팔이 떨어질 수 있는 구역에서 사람·물건을 전부 치운다 | | |
| **S-4** 무부하 확인 | 페이로드를 **전부 떼어낸다** | | |
| **S-5** E-Stop 리셋 거동 | 실제로 E-Stop을 작동시키고 리셋한다 | 차단·복귀가 예상대로인가 | **S-2·S-3·S-4가 끝나기 전에는 절대 하지 않는다** — 이때 팔이 지지 없이 서 있으면 안 된다 |

**통과 조건**: S-1~S-5 증거가 다 모이고 + 사람이 판정 서명 + 복구 절차 RC-1~RC-5가 실재함을 증명 +
막히지 않은 도달 구간이 **0**.

**다시 해야 하는 때**: 구속물·마운트·페이로드·E-Stop 배선·작업대 위치 중 **하나라도 바뀌면** 무조건
재실행. 이전 통과는 그 구성에만 유효했다.

## 4. 항목별 상세 — 32개 검증 지점

### 4-0. 공통: 어떻게 돌리나

각 항목은 이미 **검사 프로그램이 다 짜여 있고, 데이터만 없어서 건너뛰기(skip) 상태**다.
실기에서 데이터를 캡처해 폴더에 넣고 환경변수로 그 폴더를 가리키면, 그 순간 검사가 실제로 돈다.

```bash
cd ~/workspace/bh_open_arm
source .venv/bin/activate

# 예: CAN 락 검증
export OPENARM_LOCK_REAL_FIXTURE=/경로/캡처폴더
pytest -q tests/wp0b01/test_reverify_hook.py
```

환경변수를 안 걸면 **"건너뜀 + 이유"** 로 표시된다. 이건 정상이다 — 가짜로 통과시키지 않는다는
뜻이다. 걸면 실제 판정이 나온다.

폴더에는 보통 **캡처한 원본 파일들 + `expected.json`**(기대값)을 넣는다. 항목마다 파일 이름이
다르고, 건너뛸 때 나오는 메시지에 **정확히 뭘 넣어야 하는지 적혀 있다.** 먼저 그 메시지를 읽어라:

```bash
pytest -q tests/wp0b01/test_reverify_hook.py -rs   # -rs = 건너뛴 이유 출력
```

### 4-1. 2부 — 통신·모터 확인 (토크 OFF)

전기만 통하고 팔은 안 움직인다. 가장 먼저 하는 이유: 통신이 안 되면 나머지가 전부 무의미하다.

| 환경변수 | 테스트 | 사람이 하는 일 / 캡처할 것 |
|---|---|---|

### 4-2. 3부 — 영점 잡기 (토크 계속 OFF)

**여기가 가장 손이 많이 가는 단계다.** 팔이 "0도"라고 믿는 위치를 물리적으로 정해주는 일이다.

프로젝트에서 `RESUME-1-02-ZERO` 라고 부르는 재개 지점이 이것이다.

**사람이 하는 일 (순서 고정):**

1. **전원이 꺼진 상태에서** 팔을 손으로 움직여 기준 자세(rest)에 맞춘다. 화면에 기준 자세 사진과
   3D 뷰가 뜬다.
2. 기계식 지그를 쓰거나, 하드스톱(기계적 끝)에 살짝 붙여 기준면을 만든다. 어느 방법을 썼는지
   기록된다(`zero_method`).
3. 화면에서 **명시적으로 "영점 설정"을 누른다.** 여기서만 0xFE(영점) 신호가 나간다.
4. 프로그램이 다시 읽어서(readback) 실제 각도와 기대 각도의 차이를 관절별로 계산한다.
   **관절당 ±0.5° 이내**여야 한다. 넘으면 다시 한다.
5. **전원을 껐다 켠 뒤 다시 연결**해서 영점이 살아남았는지 확인한다.
   - 살아남으면: 영점 영속성 확정
   - 안 살아남으면: "매 전원 세션마다 영점 다시 잡기" 강제 플래그가 켜진다
   - **둘 다 유효한 결과다.** 안 살아남는다고 실패가 아니라, 그 사실을 확정하는 게 목적이다

## 5. 🔴 절대 하면 안 되는 것

### 5-1. 페이로드를 매단 채 E-Stop을 시험하지 마라

`docs/v1/plan/04-리스크-및-안전-브링업-게이트.md` §4.4가 이것만으로 한 절을 쓴다.

무엇이 일어나는지 순서대로:

1. E-Stop → 모터 전원 차단 → **팔이 떨어진다** (여기까지는 시끄럽고 눈에 보인다)
2. 그다음 4~8단계는 **전부 조용하다** — 영점이 깨지고, 그 위에서 잡은 마찰 데이터가 오염되고,
   그 데이터로 만든 모델이 틀리고…
3. 그리고 오염은 **마찰 데이터를 뽑는 시점이 아니라 그걸 쓰는 시점**에 드러난다. 즉 몇 단계 뒤에.

→ 무부하(S-4)를 먼저 확인하고 E-Stop(S-5)을 시험하는 순서가 여기서 나온다.

### 5-2. 복구 절차 없이 시작하지 마라

정전이나 E-Stop 이후 어떻게 복구하는지가 **먼저 코드로 존재하고 검증돼야** 안전 게이트를
시작할 수 있다. 핵심 5가지(`RC-1`~`RC-5`):

| | 요구 | 왜 |
|---|---|---|
| RC-1 | 전원 재인가 후 **모터를 켜기 전에** 전 관절 위치부터 읽는다 | 어디 있는지 모르고 켜면 안 된다 |
| RC-2 | 영점이 살아있는지 **기대값과 실측값의 차이**로 검사, 허용치를 넘으면 다시 잡으라고 요구 | |
| RC-3 | **떨어진 자세가 충돌 상태인지 3D로 판정.** 충돌이면 자동 복귀 금지, 사람이 손으로 푼다 | 충돌 상태에서 자동으로 움직이면 부순다 |
| RC-4 | E-Stop 해제 후 **자동으로 따라가기 재개 금지.** 첫 명령의 목표 위치는 **반드시 실측 각도** | 상류 라이브러리에 `q_des=0`을 풀 게인으로 1프레임 쏘는 버그가 있다(공개 이슈 #66) — 그대로 두면 팔이 튄다 |
| RC-5 | E-Stop 후 **논리 세션을 새로 열지 않는다.** 통신만 다시 여는 별도 연산(`reopen_transport()`)을 쓴다 | 다시 연결하면 자동 영점이 돌아 영점이 날아간다 |

### 5-3. 시뮬레이션 결과를 물리 안전의 증거로 내지 마라

특히 S-2(기계적 구속). 시뮬은 시각화 보조일 뿐이다. 시뮬 낙하 결과를 커버리지 근거로 제출하면
그 자체가 실패 사유다.

### 5-4. 리그를 바꾸고 이전 통과를 재활용하지 마라

구속물·마운트·페이로드·E-Stop 배선·작업대 위치 중 하나라도 바뀌면 안전 게이트 재실행이다.
어디부터 다시 하는지는 §4.5 "재실행 진입점 규칙" 표에 있다.

## 6. 통과했는지 어떻게 아나

### 각 항목

```bash
export OPENARM_<항목>_REAL_FIXTURE=/캡처/폴더
pytest -q tests/<해당폴더> -rs
```

- 초록 = 실제 데이터로 검사가 돌아서 통과
- 빨강 = 실제로 실패. 메시지에 어느 값이 얼마나 벗어났는지 나온다
- 건너뜀(skip) = **아직 데이터가 없다.** 통과가 아니다

### 전체

```bash
./scripts/gates.sh        # 게이트 13종 전부. 판정은 종료 코드로 한다
```

호스팅 CI는 없다(연구개발 단계라 제거). **`scripts/gates.sh`의 목록이 곧 계약이다** —
거기 없는 검사는 아무도 돌리지 않는다.

### 기록

각 단계의 증거(로그·캡처·판정)는 남겨야 한다. 나중에 "이 수치 어디서 나왔냐"는 질문에 답할 수
있어야 하고, 리그를 바꾸면 이전 증거는 **못 쓴다**는 규칙이 있기 때문이다.
